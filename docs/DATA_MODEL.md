# 데이터 모델과 입력 규칙

정확한 속성명·유형·수식은 `teacher_planner/blueprint.json`에 있다. Python 설치와 MCP 설치가 같은 설계 원본을 사용한다. `학년도`는 모든 행의 숫자 속성이고 `보관`은 체크박스다. Notion에서 직접 추가한 행에도 학년도를 입력해야 현재 학년도 뷰에 표시된다. 누락 행은 DB의 기본 전체 뷰에서 찾는다.

| DB | 기록 단위 | 핵심 관계 |
| --- | --- | --- |
| 학급 | 학년도별 담당 반 | 담당 교과 다중 선택 |
| 학생 명단 | 학생 한 명 | 학급 |
| 담당 영역 | 지속 관리 분야 | 다른 업무의 기준 |
| 프로젝트 | 완료 기준이 있는 목표 | 영역 |
| 수업·업무 자료 | 원문 또는 참고 자료 하나 | 영역, 프로젝트 |
| 업무·일정 | 할 일 또는 일정 하나 | 학급, 영역, 프로젝트 |
| 교사 시간표 | 실제 날짜의 교시 하나 | 학급, 업무·일정 |
| 수업 진도 | 반·교과별 단원 하나 | 학급, 시간표, 자료 |
| 상담 기록 | 상담 한 회 | 학생, 후속 업무 |
| 출결 체크 | 학생·날짜, 필요시 교시 | 학생, 학급 |
| 제출물 체크 | 학생별 제출 항목 하나 | 학생, 학급, 업무·일정 |
| 평가·채점 | 반별 평가 하나 | 학급, 업무·일정, 기준표 |
| 학부모 연락 | 연락 한 회 | 학생, 후속 업무 |
| 회의록·결정 사항 | 회의 한 회 | 프로젝트, 후속 업무 |

## 한 번 입력한 일정을 여러 곳에서 보기

일정 원본은 업무·일정 DB다. 상담·평가·회의·연락에서 캘린더에 보일 일이 생기면 업무·일정에 한 행을 만들고 관계로 연결한다. **관계만 연결하면 날짜가 자동 복사되는 것은 아니다.** ‘다음 주 화요일 상담 후속 확인을 일정에 넣어줘’처럼 AI에게 요청하거나 직접 등록한다. 학생 기록에는 상세 내용, 일반 일정에는 중립적 제목을 쓴다.

시간표 파일 가져오기와 컴시간 웹 동기화는 예외적으로 시간표와 연결 일정을 함께 갱신한다. 둘은 `외부 ID`로 대응되며 같은 경로로 재실행해도 캘린더에 수업을 중복 생성하지 않는다. 해당 가져오기 기능은 시간표 일정의 제목·시간·학급·종류·상태를 관리한다. 우선순위·메모·보관 여부는 기존 값을 유지한다. 파일 방식은 원본 파일을 수정해 다시 가져오고, 웹 방식은 컴시간 원본과 로컬 교시 시각·이름 설정을 확인해 다시 동기화한다.

파일 시간표의 고유키는 학년도·설정한 교사·실제 날짜·교시이고, 컴시간 웹 고유키는 학교 코드·교사 번호·실제 날짜·교시다. 같은 경로로 재실행할 때 기존 행을 갱신하며, 파일로 넣은 수업과 웹 수업을 자동 통합하지는 않는다. Notion 학급 연결은 기존 수첩의 반 설정을 사용한다. 웹 응답의 주간 날짜를 검증한 후 정규 시간표 행으로 변환한다. 조회가 실패하거나 요청한 주가 제공되지 않으면 쓰기를 하지 않는다. 파일이나 웹에서 빠진 행만으로 휴강을 추정하지 않으며, 명시적인 휴강 처리만 연결 일정을 취소한다. 자세한 설정은 [COMCIGAN.md](COMCIGAN.md)를 참고한다.

컴시간 첫 동기화는 학교 코드·교사 번호·교사 이름을 로컬 설치 상태에 연결한다. 이후 조회 대상이 바뀌면 기존 날짜·교시 행을 다른 교사의 수업으로 덮어쓰지 않도록 중단한다. 교시 시작·종료 시각을 별도로 설정하지 않았다면 날짜만 기록하며 수업 길이를 추정하지 않는다.

## 진도와 채점률

- 진도율 = 완료 차시 / 계획 차시 × 100. 0~100으로 제한하며 계획이 0이면 0이다.
- 채점률 = 채점 완료 인원 / 대상 인원 × 100. 동일한 0 나눗셈 방어가 있다.
- 두 값은 숫자 퍼센트(25는 25%)다. 상태는 교사가 별도로 변경한다.
- 교시가 지났다고 수업 완료 차시를 자동 증가시키지 않는다. 휴강·보강은 교사가 반영한다.
- 지연은 `마감 날짜 < 오늘`이고 완료·취소가 아닌 업무다. 당일 마감은 당일이 지나기 전까지 지연으로 표시하지 않는다. Notion의 사용자 시간대도 Asia/Seoul로 맞춘다.

## 기록 입력 예시

```text
가상학생 A → 1학년 1반
상담 기록 → 학생 A, 상담일, 관찰 사실, 합의 사항
후속 업무 → 중립적인 제목 ‘후속 확인’, 일정, P2, 업무 분류=상담
상담 기록.후속 업무 → 위 일정 행
```

학부모 전화번호·주소·민감한 진단 필드는 기본으로 만들지 않는다. 개인별 성적 원점수 대신 평가별 채점 현황을 관리한다. 실제 학교 규정과 사용 범위에 맞추어 교사가 필요한 기록을 선택한다. 자동 메시지 발송 기능은 없다.
