# 데이터 모델과 입력 규칙

정확한 속성명·유형·수식은 `teacher_planner/blueprint.json`에 있다. Python 설치와 MCP 설치가 같은 설계 원본을 사용한다. `학년도`는 모든 행의 숫자 속성이고 `보관`은 체크박스다. Notion에서 직접 추가한 행에도 학년도를 입력해야 현재 학년도 뷰에 표시된다. 누락 행은 DB의 기본 전체 뷰에서 찾는다.

| DB | 기록 단위 | 핵심 관계 |
| --- | --- | --- |
| 학급 | 학년도별 담당 반 | 담당 교과 다중 선택 |

| 학교 계정 관리 | 업무 서비스 또는 계정 하나 | 관리 담당과 외부 보관 위치 안내 |

## 학생 페이지의 누적 상담 이력

`상담 기록.학생`과 `학생 명단.상담 기록`은 같은 양방향 관계다. 새 상담의 `학생` 속성에서 해당 학생을 선택하면 학생 쪽 관계에도 같은 상담 페이지가 나타난다. 상담 본문을 학생 페이지로 복사하지 않고 원본 상담 한 건을 연결한다. 과거 상담도 이미 그 학생과 연결되어 있으면 함께 확인할 수 있다.

학생별 이력은 **그 학생 페이지에 연결된 전체 기간의 상담**을 대상으로 한다. 오늘·최근 날짜·현재 학년도 필터로 과거를 제외하지 않는다. 이름이나 본문에 학생 이름만 적은 상담은 자동 연결되지 않으며, 다른 학년도 수첩의 동명 학생도 자동으로 합치지 않는다. 누락된 연결은 실제 학생·학급·학생 ID를 확인한 뒤 지정한다.

새 Python REST 설치는 양방향 관계 속성을 만들며 학생 페이지의 `상담 기록` 속성에서 기록을 연다. 이 설치 경로는 학생 DB의 공통 페이지 레이아웃(`page_layout`)을 설정하지 않는다. MCP/Notion UI에서 별도로 공통 레이아웃의 관계 보기를 구성하면 기존·신규 학생 페이지 모두에서 누적 상담 이력을 표나 목록으로 볼 수 있다. 도구가 정렬을 지원하면 `상담일` 기준 날짜순으로 설정하고 실제 결과를 확인한다. 관계 속성 생성만으로 이 목록까지 완성됐다고 안내하지 않는다. [Notion 관계](https://www.notion.com/help/relations-and-rollups), [공통 페이지 레이아웃](https://www.notion.com/help/layouts)

기존 수첩의 단방향 관계를 바꾸기 전에는 모든 상담 페이지의 학생 관계 ID 배열을 비공개로 저장한다. 양방향 전환 후 연결이 유지되었는지 재조회하고 빠진 값은 사전 저장한 정확한 배열로만 복원한다. 스키마 변경 성공이 관계 값 보존을 보장하지 않는다. 기존 상담 본문·학생 메모·다른 속성·보기를 유지하며 상담이나 학생을 새로 복제하거나 이름만으로 연결을 추정하지 않는다. 학생별 본문에 고정 목록을 반복 삽입하지 않는다. 상세 절차는 [MCP 설치 안내](INSTALL_WITH_MCP.md#학생-페이지에-누적-상담-이력-연결)를 따른다.

## 한 번 입력한 일정을 여러 곳에서 보기

일정 원본은 업무·일정 DB다. 상담·평가·회의·연락에서 캘린더에 보일 일이 생기면 업무·일정에 한 행을 만들고 관계로 연결한다. **관계만 연결하면 날짜가 자동 복사되는 것은 아니다.** ‘다음 주 화요일 상담 후속 확인을 일정에 넣어줘’처럼 AI에게 요청하거나 직접 등록한다. 학생 기록에는 상세 내용, 일반 일정에는 중립적 제목을 쓴다.

대시보드와 학사 캘린더 페이지는 같은 업무·일정 원본을 연결한다. 각 페이지의 `주간 캘린더`와 `월간 캘린더`는 한 연결 DB의 보기 탭이며 부모 database ID, data source ID, `일정` 날짜 속성을 공유한다. 학사 캘린더의 마감 탭도 같은 연결 DB에 속하지만 `마감` 속성을 사용한다. 서로 다른 페이지의 연결 블록은 별도 ID여도 원본 데이터는 공유하며 일정 행은 한 번만 저장된다. 교사 시간표 뷰는 교사 시간표 원본을 사용한다.

시간표 파일 가져오기와 컴시간 웹 동기화는 교사 시간표 DB에 수업을 추가·갱신한 뒤 주간 격자를 갱신한다. 홈과 교과 페이지에는 같은 교사 시간표 원본과 같은 표시 주간을 사용하는 세로 교시·수업 시간, 가로 월~금의 격자를 표시한다. 오늘 날짜 행만 보여 주는 `오늘 수업` 목록은 관리용 보기로 유지한다. 원본 DB의 목록형 보기는 격자 아래 `시간표 원본 · 관리용` 제목의 기본 닫힌 접기 영역에서 확인·수정한다. 공통 배치 계약에 따라 실제 UI의 닫힌 상태를 검증하며, 도구 미지원으로 관리 목록이 펼쳐진 중간 결과는 배치 확인 대기로 남긴다. 수업은 업무·일정·To-Do·학사 캘린더에 복사하지 않는다. 파일 방식은 원본 파일을 수정해 다시 가져오고, 웹 방식은 컴시간 원본과 로컬 교시 시각·이름 설정을 확인해 다시 동기화한다.

기존 스키마의 `업무·일정` 관계 속성은 호환성을 위해 남기지만 가져오기가 연결·수리·해제하지 않는다. 이전 버전에서 복사했던 업무·일정 행도 그대로 두며 갱신·취소·삭제하지 않는다. 과거 복사본 정리는 실제 대상과 기간을 확인한 별도 작업이다.

파일 시간표의 고유키는 학년도·설정한 교사·실제 날짜·교시이고, 컴시간 웹 고유키는 학교 코드·교사 번호·실제 날짜·교시다. 같은 경로로 재실행할 때 기존 행을 갱신하며, 파일로 넣은 수업과 웹 수업을 자동 통합하지는 않는다. Notion 학급 연결은 기존 수첩의 반 설정을 사용한다. 웹 응답의 주간 날짜를 검증한 후 정규 시간표 행으로 변환한다. 조회가 실패하거나 요청한 주가 제공되지 않으면 쓰기를 하지 않는다. 파일이나 웹에서 빠진 행만으로 휴강을 추정하지 않으며, 명시적인 휴강 처리만 시간표의 상태에 반영한다. 자세한 설정은 [COMCIGAN.md](COMCIGAN.md)를 참고한다.

컴시간 첫 동기화는 학교 코드·교사 번호·교사 이름을 로컬 설치 상태에 연결한다. 이후 조회 대상이 바뀌면 기존 날짜·교시 행을 다른 교사의 수업으로 덮어쓰지 않도록 중단한다. 교시 시작·종료 시각을 별도로 설정하지 않았다면 날짜만 기록하며 수업 길이를 추정하지 않는다.

새 설치의 기본 시간표 격자는 교사 시간표 DB의 특정 주를 보여 주는 표시용 표다. 교과 페이지의 원본 `synced_block`에 표시 주간 안내·격자·동기화 안내를 두고 홈에서 참조한다. 격자와 표시 주간 안내 ID는 각각 하나이며 Python REST도 같은 공유 구조를 사용한다. 시간표 가져오기·동기화 후 해당 주 원격 기록을 다시 읽어 공유 원본 안의 격자·표시 주간 안내 자식 블록을 갱신한다. `synced_block` 객체 자체를 갱신하지 않으며 홈과 교과 페이지에는 같은 결과가 표시된다. 일부 행만 입력해도 원격에 남아 있는 기존 수업을 표시에서 임의로 지우지 않는다. 격자를 직접 편집해도 시간표 DB로 역전송되지는 않는다. 공유 표의 수동 변경은 두 페이지의 격자에 함께 표시될 수 있다. 격자의 주 선택과 표시 범위는 [DEFAULT_TEMPLATE.md](DEFAULT_TEMPLATE.md#요일교시-주간-시간표)에 있다.

## NEIS 공개 학사일정

공개 학사일정은 기존 업무·일정 원본의 `일정`에 시각 없는 날짜 또는 양 끝을 포함하는 날짜 범위로 기록한다. 같은 교육청·학교·학년도·학교과정·주야과정에서 이름이 같고 달력상 연속된 일자는 한 행사 페이지로 묶는다. 중간 일자가 없으면 별도 구간으로 두며 주말을 임의로 채우지 않는다. 별도 DB·스키마·보기는 만들지 않으며 대시보드와 학사 캘린더 페이지의 주간·월간 탭을 공유한다. 학교 행사의 날짜만으로 개인 업무의 마감을 추정하지 않는다.

교육청·학교·날짜·행사 이름·학교과정·주야과정의 조합을 원본 일자의 외부 식별값으로 사용한다. 설치 상태는 그룹 대표 페이지와 일자별 소속을 보존하며, 같은 그룹과 겹치는 날짜가 있는 기간 확장은 대표 페이지 ID를 유지한다. 대상 학년은 원본이 명시한 학년만 표시하며 미상 값을 전체 학년으로 추정하지 않는다. 바뀐 설명·대상 학년·휴업 구분·출처는 일정 페이지의 연동 전용 콜아웃에 날짜별로 반영한다. 연동은 `이름`·`일정`과 전용 콜아웃 내용을 관리한다. 새 일정의 종류는 행사, 상태는 예정, 업무 분류는 행정으로 시작한다. 기존 우선순위·메모·보관·교사가 변경한 상태·분류와 다른 본문은 보존한다. 같은 내용을 재조회하면 Notion 쓰기를 하지 않는다.

이미 만든 날짜별 페이지를 통합할 때는 대표 페이지 하나를 유지하고 나머지 원본에 `보관=true`를 적용한다. 원본의 수동 본문·메모·관계를 보존하고 대표 페이지에서 원본 링크를 제공한다. Python 경로의 첫 통합은 `--merge-existing`을 명시하며 MCP 경로는 기존 설치 기록과 도구를 사용한다. 원본에 영구 행사 ID가 없으므로 이름이 바뀌거나 날짜가 기존 그룹과 겹침 없이 이동한 행사는 새 기록이 되고 이전 기록은 남는다. 부분 조회로 기존 기간을 축소하거나 모호하게 분리된 그룹을 자동 재구성하지 않는다. 조회 결과의 누락을 자동 삭제·취소로 해석하지 않는다. 수동 일정이나 이전 버전의 시간표 복사 일정과도 자동 통합하지 않는다. 실제 학교·기간을 확인한 뒤 [SCHOOL_CALENDAR.md](SCHOOL_CALENDAR.md)의 규칙으로 반영한다.

## 급식 표시와 기록 양식

급식은 홈에 있는 연동 전용 콜아웃에 표시하며 별도 DB·속성·일정 행을 만들지 않는다. 학교·기준 날짜·확인 시각과 제공된 식단 정보를 보여 준다. 원본 메뉴의 알레르기 번호는 보존하고 공개 자료 없음과 조회 실패를 구분한다. 표시 갱신은 [MEALS.md](MEALS.md)의 별도 명령으로 수행한다.

양식은 `양식 모음` 아래의 빈 작성 구조를 갖춘 페이지다. 자동 생성된 학생 기록이나 DB 네이티브 템플릿이 아니다. DB 기록으로 사용할 때는 새 행의 본문에 복사하고 학년도·날짜·학생·학급·관계 속성을 별도로 입력한다. 양식을 복사한다고 후속 일정·상담 관계·시간표 행이 자동 생성되지 않는다. 설정과 각 양식의 사용 조건은 [FORMS.md](FORMS.md)에 있다.

## 오늘 보기와 날짜 수식

`오늘 수업`, `오늘 상담`, `오늘 출결`은 각각 수업일·상담일·출결 날짜를 오늘 날짜와 비교하는 수식이다. 날짜가 비면 false다. 오늘 보기는 저장된 행을 필터링하며 명단만으로 출결 행이나 상담 기록을 자동 생성하지 않는다. Notion의 사용자 시간대를 Asia/Seoul로 맞춰 날짜 경계를 확인한다.

업무의 `마감 남은 일`과 평가의 `평가 남은 일`은 시각을 제거한 달력 날짜 차이다. 마감이 오늘이면 0, 내일이면 1, 어제이면 -1이다. 빈 날짜·완료·취소는 숫자 0을 반환하지만 관련 임박/예정 수식은 false, D-Day 표시는 빈 문자열이므로 오늘 일정으로 해석하지 않는다.

- 업무 `마감 임박`: 완료·취소가 아니고 오늘부터 7일 이내에 마감이 있는 경우.
- 평가 `평가 예정`: 완료·취소가 아니고 오늘부터 30일 이내에 평가가 있는 경우.
- `D-Day`·`평가 D-Day`: 오늘은 D-Day, 앞으로 n일은 D-n, 지난 n일은 D+n.

이 값은 각 행의 수식이며 전체 출석률이나 평균 진도를 자동 집계하는 카드가 아니다. 모의 API 검증은 실제 Notion 수식 실행 결과를 대체하지 않는다.

## 학생 관찰과 조회·종례 메모

학생 명단의 `관찰 태그`는 학습·관계·생활·출결·후속 확인을 선택하는 다중 선택이고 `집중 관찰`은 체크박스다. 태그가 하나라도 있거나 집중 관찰을 체크한 학생을 관찰 보기에서 찾는다. 진단이나 개인 성적을 추정하는 기능은 아니다.

학급 페이지의 조회·종례 콜아웃은 별도 수동 메모 블록이다. 학생 DB로 자동 복사되거나 날짜별 행으로 자동 저장되지 않는다. 지속 추적할 내용은 학생 메모와 상담 원본에 남긴다. 학생 갤러리는 같은 학생 DB의 보기이며 참고 이미지의 인물 사진을 기본값으로 넣지 않는다.

## 진도와 채점률

- 진도는 하나의 원본 DB를 사용한다. `학기`를 `1학기` 또는 `2학기`로 선택하면 교과 페이지의 해당 학기 뷰에 나타난다. 학기를 선택하지 않은 행은 전체·반별·교과별 진도에서 찾을 수 있으며, 날짜만으로 학기를 추정하지 않는다.
- 보강 필요 보기는 `상태=보강 필요`인 기록만 사용하며 낮은 진도율만으로 보강 필요를 추정하지 않는다.
- 진도율 = 완료 차시 / 계획 차시 × 100. 0~100으로 제한하며 계획이 0이면 0이다.
- 채점률 = 채점 완료 인원 / 대상 인원 × 100. 동일한 0 나눗셈 방어가 있다.
- 두 값은 숫자 퍼센트(25는 25%)다. 상태는 교사가 별도로 변경한다.
- 교시가 지났다고 수업 완료 차시를 자동 증가시키지 않는다. 휴강·보강은 교사가 반영한다.
- 지연은 `마감 날짜 < 오늘`이고 완료·취소가 아닌 업무다. 당일 마감은 당일이 지나기 전까지 지연으로 표시하지 않는다. Notion의 사용자 시간대도 Asia/Seoul로 맞춘다.

## 기록 입력 예시

```text
가상학생 A → 1학년 1반
상담 기록 → 학생 A, 상담일, 관찰 사실, 합의 사항
후속 업무 → 중립적인 제목 ‘후속 확인’, 일정, P2, 업무 분류=상담
상담 기록.후속 업무 → 위 일정 행
```

학부모 전화번호·주소·민감한 진단 필드는 기본으로 만들지 않는다. 개인별 성적 원점수 대신 평가별 채점 현황을 관리한다. 실제 학교 규정과 사용 범위에 맞추어 교사가 필요한 기록을 선택한다. 자동 메시지 발송 기능은 없다.

## 교직원 연락망과 학교 계정 관리

두 DB는 선택 기능이며 실기록은 기본값에 넣지 않는다. 이름·학년도·보관 속성과 함께 다음 항목을 사용한다.

| DB | 입력 항목 |
| --- | --- |
| 교직원 연락망 | 부서, 직책, 교내연락처, 이메일, 담당 업무, 메모 |
| 학교 계정 관리 | 서비스 이름, 접속 URL, 계정 ID, 관리 담당, 보관 위치, 메모 |

교내연락처는 전화번호 속성, 이메일은 이메일 속성이다. 학교 계정의 `보관 위치`는 기존 비밀번호 관리 도구 등 외부 보관 위치의 URL이다. 비밀번호·복구 코드·토큰을 보관하는 필드는 만들지 않으며 메모에도 비밀값을 넣지 않는다. 두 DB가 `운영 자료`에 있다는 이유만으로 공개 공유해도 되는 자료라고 간주하지 않는다.
