# 예시 수첩을 보며 AI와 함께 수정하기

생성한 Notion 수첩을 직접 사용해 보고 AI에게 바꾸고 싶은 부분을 요청할 수 있습니다. AI는 기존 수첩을 읽고 요청한 부분을 수정하며, 다른 교사에게도 적용할 공통 개선은 저장소의 템플릿에도 반영합니다. 매번 수첩을 새로 만들 필요는 없습니다.

## 이렇게 요청하세요

대상 화면과 원하는 결과를 함께 말하면 충분합니다. 이미 이 대화에서 만든 수첩이라면 다시 설치를 요청하지 않아도 됩니다.

> 홈에서 오늘 급식을 주간 시간표 바로 아래로 옮겨 줘. 같은 배치를 저장소 기본 템플릿에도 반영해 줘.

> 학생 상담 기록 양식에 ‘다음 상담에서 확인할 질문’을 추가해 줘. 이미 작성한 상담 내용은 유지해 줘.

> 내 수첩의 할 일 기본 정렬을 마감일 순서로 바꿔 줘. 이 정렬은 내 수첩에서만 사용할게.

새 대화나 다른 AI에서 이어갈 때는 이 저장소와 수정할 Notion 페이지 링크를 알려 주세요. 로컬 설치 기록이 있다면 AI가 비공개 작업 폴더에서 읽게 합니다. 공개 저장소나 공개 이슈에 설치 기록을 첨부할 필요는 없습니다.

## 한 번의 수정이 반영되는 곳

| 변경 내용 | 기존 Notion 수첩 | 저장소 |
| --- | --- | --- |
| 공통 화면 배치·보기·속성·빈 양식 개선 | 요청한 기존 페이지·DB를 수정 | 기본 템플릿·관련 코드·설명을 함께 수정 |
| 개인 반·교과·즐겨찾기·개인 표시 취향 | 해당 수첩과 비공개 설정에 반영 | 실정보를 넣지 않으며, 필요한 경우 일반화된 설정 기능만 추가 |
| 학생 기록·상담·출결·개인 업무 입력 | 해당 원본 기록에 반영 | 내용과 개인 식별값을 넣지 않음 |

공통 템플릿 변경은 이후 새로 설치할 수첩에도 적용됩니다. 이미 설치된 모든 수첩을 자동 변경하는 기능은 아닙니다. 다른 교사의 수첩은 그 교사가 변경을 요청한 범위에서 별도로 수정합니다.

## AI가 진행하는 순서

1. **현재 상태 확인:** 비공개 설치 기록과 실제 Notion 페이지를 읽어 같은 수첩인지 확인합니다. 사용자가 직접 편집한 내용, 원본 DB, 연결 보기와 양식의 현재 상태를 확인합니다.
2. **요청 범위 확정:** 기존 대화의 승인과 선호를 재사용합니다. 개인 설정인지 공통 템플릿 개선인지 판단하고, 판단에 필요한 정보가 없을 때만 묻습니다.
3. **기존 수첩 수정:** 저장된 페이지·DB·data source·보기 ID를 재사용해 필요한 속성, 보기 설정, 블록만 바꿉니다. 교사가 작성한 기록과 요청하지 않은 내용은 보존합니다.
4. **공통 설계 반영:** 재사용할 개선은 `teacher_planner/blueprint.json`, `teacher_planner/dashboard.json`, 양식 정의, 관련 코드·문서 등 해당 원본에 반영합니다. 기능 변경에 필요한 검사를 실행합니다.
5. **결과 검증:** 실제 Notion을 다시 읽어 원하는 배치·필터·관계·내용이 반영됐는지 확인합니다. 저장소 검사와 실제 Notion 확인을 구분해 보고하고, 비공개 설치 기록과 변경 이력을 갱신합니다.

페이지 전체를 저장소의 초기 본문으로 덮어쓰거나 DB를 삭제한 뒤 다시 만드는 방식으로 일반 수정을 처리하지 않습니다. 기록 삭제·일괄 보관·구조 교체가 필요한 요청은 대상과 범위를 확인해 그 범위 안에서 진행합니다. 누락된 페이지나 권한 오류가 발생하면 실제 존재 여부를 확인하기 전까지 중복 생성하지 않습니다.

캘린더의 주간·월간은 같은 업무·일정 원본을 유지합니다. 홈과 교과 페이지에는 같은 교사 시간표 원본의 같은 주를 보여 주는 요일×교시 주간표를 둡니다. 교과 페이지의 표와 표시 주간을 동기화 블록으로 홈에 공유하므로 원본 반영 뒤 하나의 표를 갱신하면 두 화면에 함께 표시됩니다. 관리용 원본 목록을 접어 두어도 원본 기록을 복제하거나 삭제하지 않습니다. 화면 배치를 바꾼다는 이유로 수업을 업무·일정·To-Do에 복사하지 않습니다.

## 설치 기록과 개인 정보

MCP/커넥터로 만든 수첩은 `.local/mcp-install.json` 같은 **MCP 전용 설치 기록**을 사용합니다. Python 설치의 `.local/state.json`과 구조가 다르므로 ID를 복사해 섞거나 서로의 명령에 넘기지 않습니다. [MCP 설치 안내](INSTALL_WITH_MCP.md)와 [중단 후 복구](RECOVERY.md)를 따릅니다.

비공개 설치 기록에는 실제 생성 경로, 페이지·DB·data source·보기·블록 ID, 확인한 저장소 버전, 변경 내역을 보관합니다. 이 정보는 `.local/` 또는 `private/`에 두고 Git 추적 대상에서 제외합니다. 상태 파일에는 필요한 연결 정보만 기록하고 학생 상담 본문이나 비밀값을 불필요하게 복제하지 않습니다.

공개 저장소에는 개인 Notion 링크와 ID, 사용자·워크스페이스 ID, 실제 학생·보호자·교직원 정보, 계정 정보, API 키나 토큰을 올리지 않습니다. 공개 설명에 예시가 필요하면 가상 자료와 자리표시자를 사용합니다. 게시 전 변경 파일과 Git 추적 목록을 확인합니다.

## 요청할 때마다 이어서 수정합니다

이 과정은 AI에게 요청한 변경을 그때마다 Notion과 저장소에 반영하는 방식입니다. Notion에서 직접 바꾼 내용이 Git에 자동 저장되거나, Git의 모든 변경이 Notion에 자동 적용되는 양방향 동기화는 아닙니다.

직접 편집한 뒤에는 “현재 페이지를 읽고 이 배치를 공통 템플릿에도 반영해 줘”라고 요청할 수 있습니다. AI는 실제 페이지를 확인한 뒤 공통으로 쓸 구조만 가져옵니다. 컴시간·NEIS의 주기 조회는 별도 설정이며, [시간표](COMCIGAN.md)·[학사일정](SCHOOL_CALENDAR.md)·[급식](MEALS.md) 안내의 실행 조건을 따릅니다.

수정 완료 안내에는 바뀐 Notion 페이지 링크, 저장소 반영 내용, 실제 확인 결과와 남은 작업을 포함합니다. 쓰기 권한이나 도구 제한으로 일부를 반영하지 못했다면 완료했다고 표시하지 않습니다.
