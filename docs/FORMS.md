# 기록 양식과 Notion DB 템플릿

`양식 모음`은 제목·작성 항목·빈 기록 영역을 갖춘 재사용 페이지 모음이다. 상담 기록, 학부모 연락, 회의록, 수업 기록, 평가 계획, 조회·종례 기록의 여섯 양식을 제공한다. 학생·연락처·실제 상담 내용이나 예시 성적을 미리 넣지 않는다.

두 가지 방식으로 사용할 수 있다.

- **Python 설치·`setup-extras`**: 별도 `양식 모음`에 복사용 빈 페이지를 만든다. DB의 `새로 만들기` 메뉴에는 자동 등록하지 않는다.
- **교사가 요청한 Notion 네이티브 템플릿 등록**: 화면 조작이 가능한 AI가 기존 대상 DB의 `새로 만들기 → 새 템플릿`에서 같은 빈 작성 양식을 등록한다. 이후 교사는 해당 메뉴에서 양식을 선택해 새 기록을 만든다.

두 경로 모두 기존 DB·뷰를 사용한다. 양식 모음과 네이티브 템플릿은 함께 유지할 수 있으며, 한쪽을 수정했다고 다른 쪽이 자동 변경되지는 않는다. 실제 메뉴 등록을 확인하기 전에는 네이티브 템플릿 생성 완료로 보고하지 않는다.

## 선택

**새 수첩을 설치하기 전** `.local/config.json`의 최상위 `forms`에 필요한 키를 적는다. 기존 수첩의 추가 설치에서는 원래 config를 그대로 사용한다.

```json
{
  "forms": ["counseling", "guardian", "meeting", "lesson", "assessment", "homeroom"]
}
```

| 키 | 양식 · 미리 읽기 | 기록할 DB · 조건 |
| --- | --- | --- |
| counseling | [학생 상담 기록](../templates/forms/counseling.md) | 상담 기록 |
| guardian | [학부모 연락 기록](../templates/forms/guardian.md) | 학부모 연락 · `modules.contact` |
| meeting | [회의록 · 결정 · 후속 조치](../templates/forms/meeting.md) | 회의록·결정 사항 · `modules.meeting` |
| lesson | [수업 계획 · 성찰](../templates/forms/lesson.md) | 수업 진도 |
| assessment | [평가 계획 · 채점 기록](../templates/forms/assessment.md) | 평가·채점 현황 · `modules.assessment` |
| homeroom | [조회 · 종례 기록](../templates/forms/homeroom.md) | 수업·업무 자료 · 담당 반 중 `homeroom=true`가 있음 |

위 여섯 대상 DB 매핑은 복사해서 기록할 때와 네이티브 템플릿을 등록할 때 모두 적용한다. 연결된 보기의 이름만 보고 다른 원본 DB에 등록하지 않는다.

`forms`를 생략하면 현재 모듈·담임 설정에서 사용할 수 있는 양식을 선택한다. `[]`는 양식을 선택하지 않는 설정이며 양식 모음 페이지도 만들지 않는다. 명시적으로 적었어도 해당 모듈·담임 조건이 맞지 않는 양식은 제외한다. 양식을 추가하려고 교사가 선택하지 않은 DB 모듈을 임의로 켜지 않는다. 기존 설치 후 `forms`나 모듈을 수정하면 config 불일치로 중단한다. 양식 선택을 바꾸기 위해 상태를 초기화하거나 기존 config에 항목을 덧붙이지 않는다. 새 설정은 별도 새 수첩에 사용하거나 대상과 기록을 확인한 별도 변경 작업으로 다룬다.

## Python으로 복사용 양식 모음 만들기

새 수첩 설치는 기본 급식 안내 영역과 선택한 양식 모음을 함께 만든다. `plan` 또는 `setup-extras` 미리보기에서 실제 선택된 양식 제목을 확인한다. 기존 Python 설치에는 다음 명령으로 추가할 구성을 먼저 확인한다.

```bash
python -m teacher_planner setup-extras --config .local/config.json --state .local/state.json
python -m teacher_planner setup-extras --config .local/config.json --state .local/state.json --apply
```

`--apply`는 기존 완료 상태와 같은 config, 설치 당시 Notion 연결을 사용한다. 기존 홈·업무 페이지·DB·보기·수동 기록을 재생성하지 않는다. 추가 영역의 ID를 로컬 상태에 기록하므로 상태 파일을 보존한다. 이 명령은 NEIS 식단을 자동 조회하지 않는다.

## 요청받은 네이티브 DB 템플릿 등록

교사가 DB의 `새로 만들기`에서 양식을 선택하도록 요청했다면 기존 선택을 재사용하고 다음 순서로 진행한다. 여섯 양식을 모두 승인했다면 위 표의 여섯 DB에 각각 하나씩 등록한다. 원본 DB나 필요한 모듈이 없는 경우에는 다른 DB로 대체하거나 새 모듈을 임의로 추가하지 않는다.

1. 설치 기록과 실제 화면에서 대상 원본 DB·기존 템플릿 목록을 확인한다. 같은 이름의 양식이 이미 있으면 열어 내용을 확인하고 요청한 수정 범위에서 재사용한다. 같은 이름을 반복 생성하지 않는다.
2. 대상 DB 오른쪽 위 `새로 만들기` 옆 화살표를 열고 `새 템플릿`을 선택한다. 편집 화면 상단에서 실제 템플릿 편집 중인지, 대상 DB가 맞는지 확인한다. 일반 DB 행을 만든 것으로 대신하지 않는다.
3. 표의 양식 이름과 `작성 양식` 본문을 넣는다. 제목·빈 표·체크박스·작성 안내를 유지하고, 복사용 페이지의 `사용 방법`이나 실제 작성 기록은 가져오지 않는다. 특정 학생·보호자·학급 관계, 고정 날짜·성적을 미리 채우지 않는다. 기존 DB에 `학년도` 속성이 있으면 현재 학년도 보기에서 새 기록을 찾을 수 있도록 **해당 수첩에 설정된 학년도**를 템플릿 속성에 미리 넣을 수 있다. 공통 양식에 특정 연도를 고정하지 않으며 새 학년도 수첩에서 재사용할 때 값을 확인·갱신한다.
4. 별도 요청이 없으면 기본 템플릿 지정이나 반복 생성(`Repeat`)을 켜지 않는다. 기존 DB 스키마·보기·기록·양식 모음을 바꾸지 않는다.
5. 편집 화면을 닫고 해당 DB의 `새로 만들기` 드롭다운을 다시 열어 이름이 표시되는지 확인한다. 템플릿의 편집 메뉴로 다시 열어 본문, 수첩과 일치하는 학년도, 그 밖의 기록별 속성의 빈 값, 반복 꺼짐을 검증한다. 승인한 각 양식의 대상 DB·템플릿 이름·확인 결과를 비공개 설치 기록에 남기고, 확인된 항목만 완료로 보고한다.

화면에서 템플릿 메뉴를 사용할 수 없다면 등록까지 끝냈다고 안내하지 않는다. 복사용 본문과 확인한 대상 DB를 준비하고 남은 UI 등록 단계를 인계한다. 이 절차는 Python `setup-extras`가 네이티브 템플릿까지 설치한다는 뜻이 아니다. [Notion 데이터베이스 템플릿 안내](https://www.notion.com/help/database-templates)

등록 후에는 해당 DB의 `새로 만들기` 드롭다운에서 양식을 선택하고 새 기록에 날짜·학생·학급 등을 입력한다. 조회·종례는 기존 수업·업무 자료 DB의 속성을 사용하며 실제 날짜·학급은 본문에 적는다. 템플릿 원본에는 이번 기록의 값을 남기지 않는다.

## 복사용 양식으로 기록할 때

1. 홈에서 `양식 모음`을 열고 필요한 양식의 작성 항목을 확인한다.
2. 양식 페이지를 복제해 안내의 기록 DB로 이동하거나, 해당 DB에 새 행을 만든 뒤 `작성 양식` 본문을 복사한다. 원본은 빈 상태로 유지한다.
3. 날짜·학생·학급·관계·학년도 등의 DB 속성은 별도로 입력한다. 조회·종례는 수업·업무 자료 DB에 두고 이름·학년도·쓰임을 입력하며 실제 날짜와 학급은 본문에 적는다.
4. 상담·연락에서 후속 업무가 생기면 필요한 업무만 업무·일정에 등록하고 관계를 연결한다. 양식 복사만으로 일정이 생성되거나 내용이 다른 DB로 이동하지 않는다.

반복 사용을 원하면 위 네이티브 등록 절차를 교사가 직접 수행하거나 AI에게 요청할 수 있다. 특정 학생·반·날짜를 기본값으로 고정하지 않는다.

수업 기록 양식은 수업 진행과 다음 수업을 적는 형식이며 시간표 수업을 업무·일정·To-Do에 복사하지 않는다. 같은 학급·단원의 진도 행이 이미 있으면 기존 기록을 수정해 진도가 중복 집계되지 않도록 한다. 본문의 표·체크박스는 DB 속성을 자동 갱신하지 않으므로 완료 차시·실제 수업일·채점 현황 등은 해당 속성에 별도로 입력한다. 학부모 연락 양식을 작성해도 메시지를 자동 발송하지 않는다.

교사가 양식 본문을 수정해 사용한 경우 재실행으로 내용을 덮어쓰지 않는다. 설치된 양식을 바꾸거나 정리할 때는 실제 페이지와 기록을 확인한 별도 작업으로 진행한다. 생성 결과가 불확실하면 [RECOVERY.md](RECOVERY.md)를 따른다.
