# 교사 업무에 맞춘 PARA

사용자가 제공한 `PARA of LIGHT … .html`에서 확인한 구조는 Quick Links, Inbox, Tasks, Notes, Projects, Areas, Resources, Topics, Archives다. 원본의 속성 일부와 구역 이름은 읽을 수 있었지만 하위 페이지 원문·원본 수식은 이 HTML만으로 확인되지 않았다. 따라서 원본 수식을 복구했다고 주장하지 않으며 교사용으로 새로 설계했다.

| 원본에서 참고한 요소 | 교무수첩 적용 | 예시 |
| --- | --- | --- |
| Inbox | 업무·일정의 `상태=수집함` | 갑자기 받은 공문 처리 메모 |
| Projects | 끝과 완료 기준이 있는 프로젝트 | 현장체험학습 준비, 수행평가 운영 |
| Areas | 계속 책임지는 담당 영역 | 수업, 담임, 행정, 평가, 상담, 연수 |
| Resources / Topics | 자료 DB + 주제·교과·쓰임 | 다음 주 독해 수업에 쓸 학습지 |
| Archives | 각 DB의 보관 체크와 학년도별 보관 뷰 | 지난 학기 완료 프로젝트 |
| Tasks / Notes | 다음 행동, 회의록, 상담 기록 | 회의 결정 사항을 업무에 연결 |

자료를 쌓기보다 쓰임을 적는 취지를 `쓰임`, `다음 행동`, `완료 기준` 속성에 반영했다. 개인 건강·가족·브랜딩 등 원본의 사례는 교무수첩에 그대로 복제하지 않았다. 보관은 원본 DB의 행을 유지하므로 학생·수업·프로젝트 관계가 끊어지지 않는다.

## 중요도와 긴급도

PARA 자체를 우선순위 순서로 해석하지 않는다. 분류와 우선순위는 다른 축이다.

| 우선순위 | 기준 | 행동 |
| --- | --- | --- |
| P1 지금 | 중요하고 긴급함 | 학생 안전 관련 즉시 대응, 오늘 필수 마감 |
| P2 계획 | 중요하지만 덜 긴급함 | 다음 단원 준비, 상담 후속 계획에 시간 배정 |
| P3 처리 | 덜 중요하지만 긴급함 | 단순 회신·취합을 묶어서 처리 |
| P4 여유 | 덜 중요하고 덜 긴급함 | 여유 시간에 검토하거나 보류 |

교사가 우선순위를 정한다. AI는 제안할 수 있지만 마감이 임박했다는 이유만으로 중요도를 자동 판정하지 않는다. `우선순위 순서` 수식은 정렬용이며 미지정 항목은 5로 뒤에 둔다. 수집함에서는 미지정 업무를 따로 찾을 수 있다.

## 캘린더에 연결하기

`프로젝트 → 업무·일정 ← 담당 영역` 관계로 할 일이 어디에 기여하는지 남긴다. `일정`은 실제 실행 시간/행사 기간, `마감`은 제출 기한이다. 예를 들어 체험학습 프로젝트의 ‘안내장 작성’은 P2·행정·화요일 오후, ‘제출 완료’ 마감은 금요일이다. 주간·월간은 `일정`, 마감 캘린더는 `마감`을 기준으로 한다. 날짜가 없으면 날짜 미정 뷰에 남는다.

원본 HTML과 이미지, 작성자의 홍보 문구는 배포하지 않는다. 이 문서는 참고 구조와 새 설계의 차이를 설명하기 위해 작성했다.
