# NEIS 공개 학사일정 가져오기

NEIS 교육정보 개방 포털의 `SchoolSchedule` API에서 학교 행사를 조회하고 기존 Notion **업무·일정 DB**에 종일 일정으로 추가한다. 대시보드와 학사 캘린더 페이지의 주간·월간 탭이 같은 원본을 사용하므로 별도 DB나 캘린더를 만들지 않는다.

이 기능은 학교의 공개 행사 정보를 읽는다. 개인 NEIS 계정으로 로그인하거나 공식 출결·성적·학적을 읽고 쓰는 기능이 아니다. `dashboard.links.neis`에 넣은 업무 포털 바로가기와도 별도 기능이다. 학교 홈페이지·PDF·이미지의 범용 파싱은 이 명령의 입력 범위가 아니다.

## 필요한 값

| 항목 | 제공 방법 |
| --- | --- |
| NEIS Open API 인증키 | 로컬 환경 변수 `NEIS_API_KEY` |
| 시도교육청 코드 | `--office-code` 또는 `NEIS_OFFICE_CODE` |
| NEIS 표준학교코드 | `--school-code` 또는 `NEIS_SCHOOL_CODE` |
| 학년도 | 조회의 `--year`, 동기화의 config `academic_year` |
| Notion 반영 | 기존 `.local/config.json`, 설치 상태, `NOTION_TOKEN` |

시도교육청 코드는 영문 대문자 1개와 숫자 2개, 표준학교코드는 숫자 7자리다. NEIS 공개 데이터의 학교 정보를 기준으로 확인한다. **컴시간 학교 코드와 NEIS 표준학교코드는 서로 다른 식별값**이며 교사 번호는 필요하지 않다.

인증키가 없으면 공식 API가 5건의 샘플만 반환할 수 있으므로 이 도구는 `NEIS_API_KEY`를 필수로 요구한다. [공식 학사일정 API 안내](https://open.neis.go.kr/portal/data/service/selectServicePage.do?infId=OPEN17220190722175038389180&infSeq=2)에서 인증키 신청과 학교 정보를 확인한다. 인증키를 채팅·Git·공개 예시에 넣지 않는다.

```bash
# bash/zsh: 화면과 셸 기록에 인증키를 남기지 않는 입력
read -r -s NEIS_API_KEY
export NEIS_API_KEY
```

`.env.example`은 변수 이름 안내이며 `.env`를 자동으로 읽지 않는다. 인증키가 포함된 요청 URL이나 원본 오류 내용을 공유하지 않는다.

## 조회와 검토

```bash
python -m teacher_planner neis-calendar --office-code 시도교육청코드 --school-code 표준학교코드 --year 2026 --output .local/neis-calendar.json
```

조회는 Notion 토큰 없이 실행할 수 있다. `--year`를 생략하면 서울 기준 현재 학년도를 사용한다. 1~2월은 전년도 학년도다. 기본 범위는 해당 학년도 3월 1일부터 다음 해 2월 마지막 날까지다. `--from YYYY-MM-DD`와 `--to YYYY-MM-DD`로 각 경계를 좁힐 수 있으며 생략한 경계는 학년도 시작·끝을 사용한다. 범위는 같은 학년도 안이어야 한다. 조회 결과는 `.local/` 또는 `private/` 아래 비공개 JSON으로만 저장한다. 기본 출력은 `.local/neis-calendar.json`이다.

도구는 페이지를 끝까지 읽고 학교·기간·날짜·응답 형식을 확인한다. 일부 페이지만 받았거나 인증·네트워크·응답 검증에 실패한 결과를 완성된 학사일정으로 반영하지 않는다. 실제 조회 결과의 학교 이름과 날짜 범위가 교사의 대상 학교·학년도에 맞는지 먼저 확인한다.

## 기존 Notion 캘린더에 반영

```bash
# 공개 일정 조회와 입력 검토. Notion에 쓰지 않는다.
python -m teacher_planner neis-sync --office-code 시도교육청코드 --school-code 표준학교코드 --config .local/config.json --state .local/state.json

# 검토한 범위를 기존 수첩에 반영한다.
python -m teacher_planner neis-sync --office-code 시도교육청코드 --school-code 표준학교코드 --config .local/config.json --state .local/state.json --apply
```

`neis-sync`는 config의 학년도를 사용하며 `--year`를 받지 않는다. 조회와 동일하게 `--from`·`--to`로 범위를 좁힐 수 있다. Python 설치를 완료한 기존 수첩의 상태 경로를 지정하고 새 수첩을 다시 만들지 않는다. MCP 설치의 ID를 Python 상태로 자동 전환하지 않는다. `--apply` 없는 명령은 조회·형식 검토이며 Notion에 접속해 차이를 비교하지 않는다. 학교 행사의 날짜는 업무·일정의 `일정`에 시각 없는 날짜 또는 날짜 범위로 저장한다. 행사 시각이나 제출 마감을 추정하지 않는다.

대상 학년은 원본이 명시한 학년만 사용하며 빈 값이나 미상 표시를 전 학년으로 추정하지 않는다. 새 일정은 `종류=행사`, `상태=예정`, `업무 분류=행정`으로 시작한다. 행사 설명·대상 학년·출처 등은 해당 일정 페이지의 연동 전용 콜아웃에 남긴다. 일반 메모와 우선순위, 보관, 교사가 바꾼 상태는 유지한다. 원본 설명이 바뀌면 연동 전용 부분을 갱신하며, 교사가 추가한 다른 본문은 유지한다. `이름`·`일정`과 전용 콜아웃의 내용은 연동이 관리한다. 이 부분을 직접 고치면 다음 반영 때 원본 값으로 돌아갈 수 있으므로 개인 내용은 별도 메모·본문에 쓴다.

## 연속된 행사를 한 페이지로 묶기

같은 교육청·학교·학년도·학교과정·주야과정에서 **이름이 같고 달력상 날짜가 하루씩 연속되는 행사**는 한 페이지로 반영한다. `일정`의 시작일은 첫날, 종료일은 마지막 날이며 두 날짜를 모두 포함한다. 예를 들어 5월 12·13·14일의 `수학여행`은 `5월 12일~14일` 한 건이다. 주간·월간 탭에서도 같은 행사 페이지가 기간으로 표시된다.

이름이 같아도 중간 날짜의 기록이 없으면 별도 행사다. 금요일과 다음 월요일에만 있는 행사는 주말을 건너 합치지 않는다. 연속된 달 말·다음 달 초는 합칠 수 있지만 학년도·학교·과정이 다르면 합치지 않는다. 제목 유사도나 부분 일치로 다른 행사명을 합치지 않는다.

날짜별 설명·대상 학년·휴업 구분 등이 달라도 해당 일자 정보를 연동 전용 콜아웃에 각각 보존한다. 여러 날의 학년 정보를 하나로 뭉쳐 모든 날짜에 적용하지 않는다. 조회 JSON의 개별 원본 행사도 유지한다. `school_calendar.grouped_schedule(snapshot, config)`는 검증 후 `group_events`를 사용해 그룹별 `source_rows`·`source_ids`와 종료일 `end`가 있는 반영 단위로 바꾼다. 하루짜리는 종료일 없이 저장한다. CLI의 `event_count`는 묶은 행사 수, `daily_record_count`는 개별 일자 수다.

### 이미 날짜별 페이지를 만든 수첩

기존 날짜별 페이지를 묶으려면 같은 수첩·학교·학년도의 **3월 1일~다음 해 2월 말 전체 범위**를 조회한다. 부분 기간으로 기존 원본을 처음 통합할 수 없다. Python 설치에서는 첫 병합에 `--merge-existing`을 명시한다.

```bash
python -m teacher_planner neis-sync --office-code 시도교육청코드 --school-code 표준학교코드 --config .local/config.json --state .local/state.json --apply --merge-existing
```

기존 페이지 하나를 대표 페이지로 유지하고 기간을 확장한다. 처음 선택할 때는 보관하지 않은 기존 페이지 중 가장 이른 일자를 우선한다. 모두 보관되어 있으면 그 상태를 유지하며, 이미 저장한 대표 페이지도 바꾸지 않는다. 나머지 날짜별 페이지는 **삭제하거나 휴지통에 넣지 않고 `보관=true`로 표시**한다. 각 페이지의 수동 본문·메모·관계는 그대로 남으며 대표 페이지의 연동 영역에서 원래 페이지 링크를 확인할 수 있다. 보관된 원본은 보관함과 링크에서 열 수 있다. 되돌릴 때는 설치 기록과 원본 페이지를 확인해 병합 관계·기간·보관 상태를 함께 복원하며, 상태 파일을 지워 새로 만들지 않는다.

MCP 설치도 같은 원칙으로 기존 페이지 ID와 실제 내용을 확인한 뒤 해당 경로의 도구로 갱신한다. Python 상태로 옮기지 않는다. 기존 기록을 묶는 요청이 있으면 그 범위에서 처리하며, 단순한 재조회 요청을 다른 수동 일정이나 무관한 페이지의 보관 권한으로 확대하지 않는다.

## 같은 행사를 다시 조회할 때

원본 일자의 식별값은 교육청·학교·날짜·행사 이름·학교과정·주야과정으로 계산한다. 처음 묶을 때 선택한 대표 페이지 ID와 그 그룹에 속한 일자 식별값을 설치 상태에 보존한다. 후속 조회에서 같은 그룹의 일자가 겹치면 기간이 앞뒤로 늘어나도 기존 대표 페이지를 갱신한다. 매번 첫날이나 마지막 날로 새 페이지 ID를 만들지 않는다. 내용이 같으면 Notion 쓰기를 하지 않는다. 이전 버전의 시간표 복사 일정이나 수동 입력 일정과는 별도 출처이므로 자동 통합하지 않는다. 현재 시간표 가져오기는 교사 시간표만 갱신하고 업무·일정에 복사하지 않는다.

한 응답 페이지 안에 모든 원본 필드가 완전히 같은 행이 반복되면 한 건만 남긴다. 정규화한 내용만 같거나 학년·설명·수정일 등 원본 값이 하나라도 다르면 합치지 않고 중단한다. 서로 다른 응답 페이지에서 같은 식별값이 반복되어도 조회 중 변경 가능성이 있어 중단한다. 전체 페이지 수신 여부는 중복 제거 전 행 수로 검증하며, 저장된 조회 결과의 `source_row_count`는 원본 수신 건수, `duplicate_row_count`는 제거한 완전 동일 행 수다. 행사 식별값 계산은 바꾸지 않는다.

NEIS 응답에는 이 기능이 사용할 수 있는 영구 행사 ID가 없다. **이름이 바뀌거나 기존 그룹과 겹치는 일자가 없이 날짜가 이동하면 새 일정이 생기고 이전 일정은 남는다.** 이전 기록이 취소된 것인지, 별도 행사인지 자동으로 판단하지 않는다. 교사가 원본과 비교해 이전 기록의 상태·보관을 결정한다. 조회 결과에서 사라진 행도 자동 삭제·취소하지 않는다.

이미 묶인 기간을 가로지르는 부분 조회는 중단하며 그 결과로 전체 기간을 줄이지 않는다. 저장된 그룹의 기간 축소·분리, 또는 원본의 새 일자가 기존 두 그룹 사이를 연결하는 경우도 자동 재구성하지 않고 쓰기 전에 중단한다. 원본·기존 설치 기록을 비교해 별도 정리하며 전체 학년도 조회를 우선 사용한다. 오류를 피하려고 `neis_groups`의 소속 기록이나 상태를 초기화하지 않는다.

정상 응답의 0건 결과는 그 조회 기간에 공개된 행사가 없다는 뜻으로 다루며 기존 캘린더를 비우지 않는다. 원본 정보의 변경 지연이나 학교의 공개 범위도 있을 수 있으므로 누락을 휴업일이나 취소로 해석하지 않는다.

## 실행 중 주기 갱신

```bash
python -m teacher_planner neis-sync --office-code 시도교육청코드 --school-code 표준학교코드 --config .local/config.json --state .local/state.json --apply --watch --interval 21600
```

기본 간격은 21,600초(6시간), 최소 간격은 3,600초(1시간)다. `--watch`는 `--apply`와 함께 사용한다. 현재 프로세스가 실행되는 동안만 반복하며 자동 예약 작업·클라우드 서버를 만들지 않는다. `Ctrl+C`, PC 종료·절전·프로세스 종료 시 갱신이 멈춘다.

주기 조회는 config에서 지정한 학년도와 `--from`·`--to`의 조회 범위를 계속 사용한다. 3월이 되어도 다음 학년도 수첩이나 설정으로 자동 전환하지 않는다. 공식 자료의 적재 주기는 매일로 안내되며, 이 기능은 변경 즉시 전달받는 푸시가 아니다. [공식 학사일정 데이터 설명](https://open.neis.go.kr/portal/data/service/selectServicePage.do?infId=OPEN17220190722175038389180&infSeq=2)

## 실패와 확인

첫 일정 반영의 교육청·학교·학년도는 설치 상태에 연결된다. 최초 조회가 0건이면 학교 연결을 고정하지 않으며 코드를 확인해 다시 조회할 수 있다. 이미 연결한 학교는 이후 0건 응답에서도 유지한다. 연결 후 대상이 달라지면 중단하므로 코드와 수첩을 확인한다. 다른 학교·학년도로 바꾸기 위해 `neis_source`나 기존 상태를 지우지 않는다. 새 수첩이 필요한 경우 별도 상태 경로를 사용한다. 마지막 확인 시각과 조회 기간도 로컬 상태에 기록한다.

조회 오류가 나면 원인을 확인한 후 같은 조건으로 다시 실행한다. Notion 쓰기 도중 응답이 유실되면 `.local/state.json`을 보존하고 [복구 절차](RECOVERY.md)를 따른다. 일부 일정만 반영된 상태에서 새 설치를 시작하거나 상태를 삭제하지 않는다.

실제 학교 API 조회, 실제 Notion 반영, 오프라인 모의 테스트는 각각 구분해 보고한다. 저장소의 테스트나 설명용 화면만으로 실제 학교의 전체 학사일정 반영을 완료했다고 안내하지 않는다. 설치 후 [NEIS 확인 기준](ACCEPTANCE.md#neis-공개-학사일정을-선택한-경우)을 확인한다.
