# 설치 확인 기준

Python 경로는 `python -m teacher_planner verify --state .local/state.json`으로 원격 속성·관계·뷰·페이지·블록을 확인한다. 모의 API 테스트는 실제 Notion 화면이나 수식 실행 검증을 대신하지 않는다. 아래 항목은 실제 설치 결과에서 확인한다.

## 네 페이지와 원본

- [ ] 대시보드와 `학급 경영 & 학생 상담`, `교과 진도표 & 시간표`, `학사 캘린더 & PARA`가 같은 수첩 안에 있다.
- [ ] 네 페이지의 공통 이동 링크가 모두 실제 페이지로 열리며 순서와 제목이 일치한다.
- [ ] 루트 제목의 학년도·학기가 설정과 일치한다. 생략한 학기는 기본값 1이다.
- [ ] 기본 9개, 모두 선택했다면 16개 원본 DB가 있다. 선택하지 않은 모듈의 빈 표·메뉴가 없다.
- [ ] 모든 모듈을 선택한 계획은 네 핵심 페이지, 24개 연결 DB 블록, 46개 연결 뷰를 사용한다. 원본 뷰 59개를 합한 총 뷰 수는 105개다. `운영 자료`·`학생 기록`은 별도 원본 보관 페이지다.
- [ ] 여러 페이지의 같은 기록이 같은 원본을 사용하며 페이지별 복제 DB가 없다.
- [ ] 참고 이미지의 실제 이름·사진·전화번호·학교 URL·워크스페이스 식별값이 기본값에 없다.
- [ ] 실제 공유 범위를 확인했다. 페이지 분류·필터·숨김을 접근 권한 분리로 설명하지 않는다.
- [ ] 이전 설치 상태에서 설계가 다르면 중단하고 기존 페이지·수동 메모를 유지한다.

## MCP 보기 적용 검증

- [ ] MCP `configure` 성공 응답만으로 필터 적용을 완료 처리하지 않았다. [수식 필터 확인 절차](INSTALL_WITH_MCP.md#mcp-수식-필터의-실제-적용-확인)에 따라 원본·연결 뷰를 각각 다시 조회했다. 2026-09-28 설치에서 성공 응답 후 boolean 수식 조건 누락 사례가 관찰되었으며, 현재 사용하는 도구에서도 직접 확인한다.
- [ ] 설계에 필요한 `오늘 수업`·`오늘 상담`·`오늘 출결`·`지연`·`마감 임박`·`평가 예정` 수식 조건이 있다. 누락을 UI로 보완할 때 속성 선택 후 `값 선택 → 체크 표시됨`까지 지정했고 기존 학년도·보관·상태 및 AND/OR 조건을 보존했다.
- [ ] 다시 조회한 수식 조건에서 `resultFilter.operator = "checkbox_is"`와 `resultFilter.value.value = true`를 확인했다. 값 없는 `{ "type": "exact" }`는 완료로 처리하지 않았다. 도구 응답 구조가 다르면 문서·UI로 동등한 조건을 검증했다.
- [ ] 원본 날짜·상태에 따른 포함·제외 결과를 확인했다. 동적 수식을 고정 날짜로 대체하지 않았고, UI에서 보완한 필터를 후속 DSL 수정으로 지우지 않았다.
- [ ] 원본·연결 캘린더 각각의 실제 표시 범위를 UI에서 확인했다. `CALENDAR BY` 성공·보기 이름·고정 날짜 필터를 주간/월간 레이아웃 검증으로 대신하지 않았다.
- [ ] 원본 `우선순위 To Do`와 홈 연결 보기를 각각 다시 조회해 `외부 ID → 포함하지 않음 → neis:` 조건을 확인했다. [To-Do 분리 절차](INSTALL_WITH_MCP.md#가져온-학사일정과-to-do-분리)에 따라 기존 보관·상태·학년도 조건을 보존했고, 지원하지 않는 MCP DSL의 `NOT`을 추정하거나 `!= "neis:"`·`STARTS WITH`로 대체하지 않았다.

## 대시보드

- [ ] 홈과 교과 페이지의 요일×교시 격자는 같은 교사 시간표 원본과 같은 표시 주간을 사용한다. 오늘 수업만 보는 목록은 `오늘 수업=true` 조건의 관리용 보기로 유지한다. 현재 진행 중 수업의 자동 강조가 있다고 안내하지 않는다.
- [ ] 할 일·P1·완료·수집함이 한 업무 연결 DB의 탭이며, 완료 편집이 원본 상태에 반영된다.
- [ ] P1~P4 정렬과 미지정 후순위가 맞고 완료·취소 업무는 미완료/P1 목록에서 빠진다.
- [ ] 가져온 학사일정은 `우선순위 To Do`에서 제외되고 수동 행사·업무는 기존 조건에 따라 표시된다. 주간·월간 학사 캘린더의 필터와 학사일정 표시는 유지된다.
- [ ] 오늘 출결과 확인 필요는 선택 모듈·원본 날짜·확인 체크에 맞는 기록만 표시한다.
- [ ] 오늘 상담은 상담일이 오늘인 기록을 사용하며 빈 날짜를 오늘로 보지 않는다.
- [ ] 반별 진도와 보강 필요 탭이 같은 진도 DB를 사용한다. 보강 필요는 실제 상태로 구분한다.
- [ ] 예정 평가는 오늘부터 30일 안의 평가이며 완료·취소·날짜 미정은 빠진다.
- [ ] 임의 학생 수·출석률·평균 진도율·연결 성공 시각을 표시하지 않는다. 실제 설정한 집계만 안내한다.

## 학급 경영과 교과

- [ ] 명렬표·학생 카드·관찰 학생이 같은 학생 연결 DB의 탭이다.
- [ ] 관찰 태그가 있거나 집중 관찰을 체크한 학생이 관찰 보기에 나타난다. 사진을 넣지 않아도 카드를 사용할 수 있다.
- [ ] 학생과 상담·출결·제출물·연락 기록이 올바른 관계로 연결된다.
- [ ] `상담 기록.학생`과 `학생 명단.상담 기록`은 같은 양방향 관계이며 기존 상담·학생 본문을 복제하지 않는다. 학생 미연결 기록을 이름만으로 귀속시키지 않는다.
- [ ] 기존 단방향 관계를 전환했다면 모든 상담의 학생 관계를 사전에 저장하고 전환 후 대조했다. 누락은 정확한 사전 ID 배열로만 복원하고 양쪽 관계를 다시 확인했다.
- [ ] MCP/UI로 누적 이력 레이아웃을 구성했다면 학생 DB 공통 관계 보기가 기존·신규 학생 페이지에 적용되며, 오늘·현재 학년도 제한 없이 해당 학생의 과거 원본 상담을 보여 준다. `상담일` 정렬은 실제 지원·적용된 경우만 완료로 보고한다. Python 관계 속성 설치만으로 이 목록을 검증했다고 하지 않는다.
- [ ] 조회·종례 메모가 빈 수동 콜아웃으로 시작하고 자동 초기화·복사 기능으로 소개되지 않는다.
- [ ] 홈과 교과 페이지에는 같은 주간 시간표 격자가 기본으로 보이고 원본 DB의 목록형 보기는 격자 아래 `시간표 원본 · 관리용`으로 구분된 접기 영역 또는 별도 관리 항목에 있다. 직접 배치한 연결 뷰를 접혀 있다고 안내하지 않는다. 오늘 수업 목록은 관리용 보기로 유지된다.
- [ ] 반·교과·1학기·2학기·보강 필요 진도 탭이 하나의 원본을 사용한다. 학기 미지정 기록은 전체·반별·교과별에서 찾을 수 있다.
- [ ] 계획 차시 4 / 완료 1의 진도율은 25, 계획 0은 0이다. 교시가 지났다고 완료 차시가 자동 증가하지 않는다.
- [ ] 평가 대상 20 / 채점 완료 5의 채점률은 25다(평가 선택 시).
- [ ] 선택한 연락망·계정·평가·회의·연락·제출물로 이동할 수 있다. 계정 DB에는 비밀번호·복구 코드·토큰 필드가 없다.

## 캘린더와 PARA

- [ ] 대시보드 캘린더의 주간·월간은 한 연결 DB의 보기 탭이다.
- [ ] 학사 캘린더 페이지의 주간·월간·마감도 한 연결 DB의 탭이다. 주간·월간은 `일정`, 마감은 `마감` 속성을 사용한다.
- [ ] 같은 섹션의 탭들은 부모 database ID·data source ID가 같고, 서로 다른 페이지의 연결 DB들은 같은 업무 원본을 공유한다.
- [ ] 주간은 실제 week, 월간은 month 범위다. 같은 일정 행이 탭 전환 후에도 같은 기록이다.
- [ ] 마감이 오늘이면 D-Day, 내일이면 D-1, 어제이면 D+1이다. 시간 부분 때문에 하루가 틀어지지 않는다.
- [ ] 마감 미정·완료·취소는 D-Day가 비고 마감 임박에서 빠진다. 임박은 오늘부터 7일 이내다.
- [ ] 날짜 미정 업무를 찾을 수 있고, 마감만 있는 업무는 마감 탭에 나타난다.
- [ ] PARA 네 콜아웃은 실제 프로젝트·영역·자료·보관함으로 연결된다.
- [ ] 프로젝트 상태 보드는 같은 프로젝트 기록을 사용한다. 보관은 해당 원본의 `보관=true`이며 활성 뷰에서 빠진다.
- [ ] 상담·연락 후속 일정 제목은 상세 내용을 노출하지 않는다.

## 시간표 격자와 네이티브 화면

- [ ] 홈의 `오늘의 수업 · 주간 시간표`는 교과 페이지의 원본 `synced_block`을 참조한다. 교과 원본에는 표시 주간 안내·격자·동기화 안내가 있으며 세로 교시·수업 시간, 가로 월~금으로 읽는다. 두 페이지의 표시 주간과 셀 내용이 일치한다. 수업 시각은 학교에서 확인한 값만 사용한다. 원본 관리용 목록을 기본 시간표로 대신하지 않았다.
- [ ] 파일·컴시간 가져오기가 교사 시간표 원본을 반영한 뒤 같은 주의 원격 기록을 읽어 공유 원본의 격자·표시 주간 안내 자식 블록을 갱신한다. `synced_block` 객체 자체를 갱신하거나 페이지마다 별도 표 사본을 만들지 않는다. 오늘 날짜의 행은 오늘 수업 관리용 보기에서도 확인된다. 실학교 미연결 상태의 예시는 가상 데이터임을 표시했다.
- [ ] 같은 자료를 두 번 반영해도 한 교시당 시간표는 한 행이다. 교실·교과 변경은 기존 시간표 행을 갱신하며 업무·일정 행을 생성·갱신하지 않는다.
- [ ] 휴강은 시간표 상태에 표시하고 기록은 남긴다. 업무·일정의 상태를 바꾸거나 누락된 원본 행을 자동 삭제하지 않는다.
- [ ] 시간표 반영이 To-Do·학사 캘린더에 수업을 추가하지 않는다. 기존 `업무·일정` 관계와 이전 복사 일정도 수정·삭제하지 않는다. 과거 복사본의 정리는 별도 범위로 확인한다.
- [ ] 격자의 표시 주간과 셀이 원본에 맞게 갱신된다. 일부 수업만 입력해도 원격에 남은 같은 주 수업·공동 메모·확장한 교시 행을 보존한다. 격자 수동 편집을 원본 DB 갱신 기능으로 설명하지 않는다. 공유 표의 수동 변경은 다른 페이지에도 보일 수 있음을 원본 역전송과 구분한다.
- [ ] 빠른 실행은 실제 DB를 여는 링크이며 Notion의 새로 만들기로 입력한다. 구현하지 않은 자동화 버튼이 없다.
- [ ] NEIS·에듀파인 바로가기는 제공한 링크로 열린다. 빈 주소는 안내로 남는다. 이 설정과 NEIS 공개 학사일정 API 연결을 구분한다.
- [ ] 정확한 사용자 CSS·서체·1440px 화면·240px 사이드바를 Notion에 적용했다고 보고하지 않는다.
- [ ] 필요하면 실제 Notion UI에서 전체 너비·표 열 폭을 조정하고 모바일 순서를 확인했다.

검증용 가상 행은 제목에 `[검증]`을 붙이고 요청받은 경우 그 행만 보관한다. 실제 자료를 일괄 삭제하지 않는다. 설치 보고에는 네 페이지 URL·원본 DB 수·실제로 검증한 항목·남은 UI 설정을 기록한다.

## 컴시간 웹 연동을 선택한 경우

- [ ] 교사가 제공한 학교 코드와 교사 번호로 조회했고, 반환된 교사와 담당 수업을 확인했다.
- [ ] `comcigan-week`의 출력에는 선택한 교사만 있고, 학교 전체 교사 명단·원본 응답이 없다.
- [ ] 요청 날짜가 포함된 실제 주의 시간표다. 제공되지 않은 주에 현재 시간표를 재사용하지 않는다.
- [ ] 열람 제한으로 한 주 전체를 확인할 수 없다면 반영이 중단된다.
- [ ] 반 이름·교과가 Notion 설정과 일치한다. 필요한 이름 매핑을 확인했다.
- [ ] 교시 시각을 지정했다면 학교의 실제 시각이며, 생략했다면 시간표 수업일에 날짜만 기록된다.
- [ ] `comcigan-sync`를 `--apply` 없이 실행했을 때 Notion 쓰기가 발생하지 않는다.
- [ ] `--apply`로 같은 주를 두 번 반영해도 한 교시당 시간표 1행이며 업무·일정에 대한 생성·갱신은 없다.
- [ ] 웹에서 변경된 반·교과는 기존 날짜·교시 행을 갱신한다.
- [ ] 접속·파싱·주간 날짜 검증 실패 시 기존 Notion 시간표를 수정하지 않는다.
- [ ] 첫 반영에 사용한 학교·교사 식별 정보가 바뀌면 자동으로 덮어쓰지 않는다.
- [ ] 파일 가져오기에서 웹으로 전환했다면 같은 날짜의 기존 수업이 중복되지 않는지 확인했다. 두 경로의 행은 자동 통합되지 않는다.
- [ ] 누락된 수업을 임의 휴강으로 판단하거나 다른 주의 기록을 삭제하지 않는다.
- [ ] `--watch`는 최소 300초의 지정 간격으로 이번 주를 재조회하며, 프로세스 종료 시 갱신이 멈춘다.
- [ ] 실제 학교 조회 및 실제 Notion 쓰기 여부를 오프라인 테스트 결과와 구분해 기록했다.

## NEIS 공개 학사일정을 선택한 경우

- [ ] 교사가 확인한 시도교육청 코드·NEIS 표준학교코드·학년도를 사용했다. 컴시간 학교 코드를 재사용하지 않았다.
- [ ] 발급받은 `NEIS_API_KEY`를 로컬 환경 변수로 제공했고 키·요청 URL을 공개하지 않았다. 키 없는 5건 샘플을 전체 일정으로 반영하지 않는다.
- [ ] 조회 기간은 해당 학년도 3월 1일~다음 해 2월 말 안이며 응답의 학교·학년도·날짜가 요청과 일치한다.
- [ ] 전체 페이지를 확인했다. 부분 페이지·응답 불일치·인증·네트워크 오류에서는 기존 Notion 일정을 수정하지 않는다.
- [ ] 같은 응답 페이지 안의 완전히 동일한 원본 행만 중복 제거했다. 원본 내용이 다른 식별값 충돌과 페이지 간 반복은 중단하며, 전체 수신 건수는 중복 제거 전 기준으로 확인했다.
- [ ] `neis-calendar`는 `.local/` 또는 `private/` 아래에 조회 결과를 저장하며 Notion에 쓰지 않는다.
- [ ] `neis-sync`를 `--apply` 없이 실행하면 조회만 수행한다. Notion 차이 비교·쓰기까지 완료했다고 보고하지 않는다.
- [ ] 반영한 행사는 기존 업무·일정 원본의 종일 일정이며 주간·월간 탭에서 같은 행을 사용한다. 새 DB·스키마·뷰를 만들지 않는다.
- [ ] 같은 교육청·학교·학년도·학교과정·주야과정에서 같은 이름의 연속 일자는 시작일~마지막 날을 모두 포함하는 행사 페이지 하나다. 하루짜리의 종료일은 비어 있다.
- [ ] 중간 일자가 빠진 동명 행사와 서로 다른 이름·학교·학년도·과정은 별도 페이지다. 금요일~월요일 사이 빈 주말을 채워 합치지 않으며 달을 넘는 실제 연속 일자는 함께 표시한다.
- [ ] 날짜별 설명·대상 학년·휴업 구분을 대표 페이지의 연동 영역에서 확인할 수 있다. 개별 원본 일자 JSON을 유지하고 `event_count`와 `daily_record_count`를 구분한다.
- [ ] 기존 날짜별 페이지를 묶었다면 대표 페이지 ID·기간과 나머지 원본의 `보관=true`를 확인했다. Python 경로에서는 `--merge-existing`을 사용했고 MCP 경로에서는 기존 설치 기록을 유지했다. 삭제·휴지통 이동 없이 원본의 수동 본문·메모·관계와 대표 페이지의 원본 링크가 남아 있다.
- [ ] 같은 행사·내용을 두 번 반영하면 새 일정이나 Notion 갱신 쓰기가 생기지 않는다.
- [ ] 저장한 일자 소속과 겹치는 앞뒤 기간 확장은 같은 대표 페이지를 쓴다. 저장된 기간을 자르는 부분 조회·기간 축소·분리·기존 두 그룹 연결은 쓰기 전에 중단하며 상태 초기화로 우회하지 않는다.
- [ ] 행사 설명·대상 학년·출처 변경은 연동 전용 콜아웃에 반영하고 우선순위·메모·보관·수동 상태·다른 본문은 유지한다.
- [ ] 대상 학년 미상 값을 전 학년으로 추정하지 않는다. 행사 날짜만으로 시각·개인 업무 마감을 정하지 않는다.
- [ ] 이름 변경 또는 기존 그룹과 겹침 없이 날짜가 이동하면 새 일정이 생기고 이전 기록은 남는다. 누락·정상 0건 응답에서도 기존 행사를 자동 삭제·취소하지 않는다.
- [ ] 첫 반영 후 다른 학교·교육청·학년도 연결은 중단한다. 기존 상태를 지워 강제로 전환하지 않는다.
- [ ] 수동 일정·이전 버전의 시간표 복사 일정과 학사일정을 자동 통합하지 않는다.
- [ ] `--watch --apply`는 기본 6시간·최소 1시간 간격으로 지정 학년도·기간만 조회하며 프로세스 종료 시 멈춘다. 새 학년도로 자동 전환하지 않는다.
- [ ] 공개 학사일정 읽기와 공식 NEIS 출결·학적 쓰기를 구분한다. 실제 API 조회·Notion 반영·모의 테스트의 검증 범위를 기록했다.

## 급식 영역과 양식 추가 설치

- [ ] 새 설치 또는 `setup-extras --apply` 후 홈에 급식 안내 영역과 선택한 양식 모음 링크가 있다.
- [ ] `setup-extras`를 `--apply` 없이 실행하면 양식 목록·급식 영역 계획만 보여 주며 Notion에 쓰지 않는다.
- [ ] 기존 완료 상태·같은 config·같은 Notion 연결을 사용한다. 추가 기능만을 위해 네 업무 페이지·DB·뷰·수동 기록을 다시 만들지 않는다.
- [ ] 같은 추가 설치를 반복해도 기존 페이지·블록 ID를 재사용하고 교사가 수정한 양식 본문을 덮어쓰지 않는다.
- [ ] 기존 설치의 `forms`·모듈을 바꾼 경우 config 불일치로 중단한다. 상태를 초기화해 강제로 추가하지 않는다.
- [ ] `verify`로 급식 블록·양식 페이지의 위치와 홈 링크·기록 DB 링크를 확인했다.

## 홈 급식을 선택한 경우

- [ ] NEIS 인증키·교육청 코드·표준학교코드를 사용한다. 컴시간 학교 코드를 사용하지 않는다.
- [ ] `neis-meals`는 서울 기준 오늘 또는 지정 날짜를 조회해 `.local/`·`private/`에 저장하며 Notion에 쓰지 않는다.
- [ ] 모든 식사 행의 학교·날짜·식사 코드·필드를 검증한 뒤 중식(`meal_code=2`) 메뉴·열량만 홈의 `오늘의 중식` 콜아웃에 표시한다. 업무·일정·시간표·To-Do 행을 만들지 않는다.
- [ ] 중식 메뉴의 알레르기 번호는 홈에도 보존한다. 조식·석식·원산지·영양정보는 원본 JSON에 보존하고 홈에서 생략한다. 빈 값을 추정하거나 기존 보관 기록을 덮어쓰지 않는다.
- [ ] 학교·기준 날짜·조회 시각·출처가 함께 표시된다. 날짜가 다른 이전 식단을 오늘의 실제 조회 결과로 보고하지 않는다.
- [ ] 정상 0건 또는 조식·석식만 있는 날은 공개 중식 정보 없음으로 표시하고 다른 식사로 대체하지 않는다. 중식 미실시로 단정하지 않으며 인증·네트워크·검증 오류는 기존 식단 표시를 보존한다.
- [ ] 학사일정·급식의 기존 교육청·학교·학년도 연결과 다른 대상은 중단한다. 수첩 학년도 밖 날짜도 반영하지 않는다.
- [ ] `--apply` 없는 `meals-sync`는 조회만 수행하고, `--watch`는 `--apply`와 함께만 실행하며 명시적 `--date`를 거부한다.
- [ ] 갱신 간격은 기본 6시간·최소 1시간이고 실행 중 서울 자정에도 다시 조회한다. 프로세스 중지 후에는 마지막 날짜의 표시가 남는다.
- [ ] 실제 학교 조회·Notion 표시·모의 테스트를 구분해 검증 범위를 기록했다.

## 여섯 기록 양식

- [ ] 학생 상담, 학부모 연락, 회의록·결정·후속 조치, 수업 계획·성찰, 평가 계획·채점, 조회·종례 중 설정과 모듈·담임 조건에 맞는 양식만 있다.
- [ ] `forms` 생략은 현재 조건에 맞는 양식을 선택하고 `[]`는 양식 모음을 만들지 않는다. 필요한 양식 때문에 선택하지 않은 DB 모듈을 추가하지 않는다.
- [ ] 양식 원본은 DB 밖 보조 페이지에 있으며 실제 학생·날짜·관계·성적을 미리 넣지 않는다. 원본이 실제 기록 집계에 포함되지 않는다.
- [ ] 각 양식의 기록 DB 링크가 맞다. 조회·종례는 수업·업무 자료 DB를 안내하며 날짜·학급을 본문에 기록한다.
- [ ] 양식 복제 후 기록 DB 이동 또는 새 행에 본문 복사로 사용할 수 있다. DB 속성은 별도로 입력한다.
- [ ] DB 새로 만들기 템플릿으로 자동 등록됐다고 소개하지 않는다. 반복 사용을 위한 수동 템플릿 등록은 별도 단계다.
- [ ] 양식의 체크박스·표를 작성해도 업무·일정 생성, 출결 반영, 메시지 발송이 자동 실행되지 않는다.
