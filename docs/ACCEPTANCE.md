# 설치 확인 기준

Python 경로는 `python -m teacher_planner verify --state .local/state.json`으로 속성 유형·관계 대상·뷰 원본·캘린더 범위를 원격 확인한다. 화면 배치, 필터 동작, 수식 계산, 권한은 아래 항목을 직접 또는 Notion 도구로 확인한다. 모의 API 테스트만으로 실제 Notion 검증을 대체하지 않는다.

- [ ] 기본 9개 DB와 선택한 추가 DB만 있다. 전부 선택했다면 14개다.
- [ ] 학급·담당 교과·학년도 설정이 맞고 실학생 예시가 없다.
- [ ] 학생을 학급에, 상담을 학생에 연결할 수 있다.
- [ ] P1→P2→P3→P4 순으로 정렬되고 미지정은 뒤에 있다.
- [ ] 어제 마감의 미완료 업무는 지연, 완료·취소 업무는 지연이 아니다.
- [ ] 같은 일정 하나가 주간·월간에 모두 나타나고 주간은 실제 1주, 월간은 실제 1달이다.
- [ ] 일정 없는 업무는 날짜 미정, 마감만 있는 업무는 마감 캘린더에 나타난다.
- [ ] 보관 행은 활성 뷰에서 빠지고 보관함에서 찾을 수 있다.
- [ ] 진도 계획 4 / 완료 1은 25, 계획 0은 0이다.
- [ ] 채점 대상 20 / 완료 5는 25다(평가 모듈 선택 시).
- [ ] 상담·연락 후속 일정에는 상세 내용이 노출되지 않는다.
- [ ] 테스트 시간표를 두 번 가져와도 한 교시당 시간표 1행·일정 1행이다.
- [ ] 같은 날짜·교시의 교실·교과 변경은 기존 행을 갱신한다.
- [ ] 휴강 가져오기는 연결 일정을 취소하고 시간표 기록을 남긴다.
- [ ] 원본 파일에서 빠진 행은 자동 삭제되지 않는다.
- [ ] 상위 페이지와 학생 기록의 실제 공유 범위를 교사가 확인했다.

검증용 가상 행은 제목에 `[검증]`을 붙인다. 검증 후 교사가 원하면 해당 가상 행만 보관한다. 실데이터를 일괄 삭제하지 않는다. 설치 리포트에는 URL·DB 수·검증한 내용·남은 수동 설정을 적는다.

## 컴시간 웹 연동을 선택한 경우

- [ ] 교사가 제공한 학교 코드와 교사 번호로 조회했고, 반환된 교사와 담당 수업을 확인했다.
- [ ] `comcigan-week`의 출력에는 선택한 교사만 있고, 학교 전체 교사 명단·원본 응답이 없다.
- [ ] 요청 날짜가 포함된 실제 주의 시간표다. 제공되지 않은 주에 현재 시간표를 재사용하지 않는다.
- [ ] 열람 제한으로 한 주 전체를 확인할 수 없다면 반영이 중단된다.
- [ ] 반 이름·교과가 Notion 설정과 일치한다. 필요한 이름 매핑을 확인했다.
- [ ] 교시 시각을 지정했다면 학교의 실제 시각이며, 생략했다면 캘린더에 날짜만 표시된다.
- [ ] `comcigan-sync`를 `--apply` 없이 실행했을 때 Notion 쓰기가 발생하지 않는다.
- [ ] `--apply`로 같은 주를 두 번 반영해도 한 교시당 시간표 1행·일정 1행이다.
- [ ] 웹에서 변경된 반·교과는 기존 날짜·교시 행을 갱신한다.
- [ ] 접속·파싱·주간 날짜 검증 실패 시 기존 Notion 시간표를 수정하지 않는다.
- [ ] 첫 반영에 사용한 학교·교사 식별 정보가 바뀌면 자동으로 덮어쓰지 않는다.
- [ ] 파일 가져오기에서 웹으로 전환했다면 같은 날짜의 기존 수업이 중복되지 않는지 확인했다. 두 경로의 행은 자동 통합되지 않는다.
- [ ] 누락된 수업을 임의 휴강으로 판단하거나 다른 주의 기록을 삭제하지 않는다.
- [ ] `--watch`는 최소 300초의 지정 간격으로 이번 주를 재조회하며, 프로세스 종료 시 갱신이 멈춘다.
- [ ] 실제 학교 조회 및 실제 Notion 쓰기 여부를 오프라인 테스트 결과와 구분해 기록했다.
