# 교무수첩 기본 홈 템플릿

새 교무수첩은 사용자 제공 `노션 교무수첩 기본 템플릿` 화면의 정보 배치를 기본으로 사용한다. 원본 HTML을 가져오거나 기존 Notion을 복제하는 방식이 아니다. 이 저장소의 데이터베이스와 기능에 맞춰 새 홈을 만든다.

데이터베이스·속성·원본 뷰는 `teacher_planner/blueprint.json`, 홈 배치는 `teacher_planner/dashboard.json`을 기준으로 한다. `python -m teacher_planner plan --config .local/config.json --full`로 자신의 선택 모듈과 홈 구성을 함께 확인할 수 있다.

[기본 배치 미리보기](template-preview.png)는 가상 수업과 빈 표로 구성한 설명 이미지다. 실제 Notion 설치 화면의 캡처는 아니다.

## 배치

| 위치 | 구성 | 연결할 자료 |
| --- | --- | --- |
| 상단 왼쪽 약 62.5% | 수업 시간표 격자 | 날짜별 교사 시간표 |
| 상단 오른쪽 약 37.5% | 빠른 동작 / 즐겨찾기 | 실제 생성한 시간표·진도·할 일·아카이브·수업자료와 개인별 외부 링크 |
| 전폭 | 주황색 Things to do | 수집함·우선순위 할 일 |
| 전폭 | 파란색 회의록 | 선택한 회의록·결정 사항 |
| 가운데 왼쪽 약 21% | Class / Share / Advice | 수업자료·진도·공유 링크·상담 및 학생 자료 |
| 가운데 중앙 약 58% | 학생 명렬표 제목과 바로가기 | 학생 명단 DB |
| 가운데 오른쪽 약 21% | School / ETC | 학교 업무·연락망·학교 계정·회의·기타 할 일 |
| 가운데 영역 아래 | 실제 학생 명렬표 연결 뷰 | 현재 학년도 학생 명단 |
| 하단 | 분홍색 Schedule | 같은 업무 원본의 주간·월간 캘린더와 상세 교사 주간 시간표 |
| 하단 | 파란색 Archive | 보관한 업무 및 자료 바로가기 |

비율은 넓은 화면에서 사용할 배치 기준이다. Notion 창 폭과 모바일 표시에서는 열이 재배치될 수 있다. 원본 손글씨 구분선 이미지는 포함하지 않고 `Class / Share / Advice / School / ETC`를 네이티브 제목·구분선으로 표현한다.

넓은 화면에서는 Notion 페이지의 `··· → 전체 너비`를 켜면 7열 시간표를 보기 편하다. 현재 REST 생성 명세에는 전체 너비 설정이 없어 Python 설치가 이 UI 설정까지 적용했다고 보고하지 않는다. 표 열 폭도 실제 화면에서 학교 이름·교과명 길이에 맞춰 조정한다.

자료의 원본 DB는 `운영 자료`와 `학생 기록` 하위 페이지에 유지한다. 홈의 DB 뷰는 해당 원본을 연결하며, 같은 내용을 새 DB로 복사하지 않는다. 상단 시간표 격자는 아래에서 설명하는 별도 표시용 표다. P1~P4, PARA, 상담, 진도, 선택한 출결·평가·연락·회의 기능을 계속 사용할 수 있다. 교직원 연락망과 학교 계정 관리도 선택한 경우에만 추가한다.

## Python과 MCP의 배치 차이

Python은 Notion REST API로 홈을 구성한다. 연결 뷰를 만들 때 사용하는 `create_database.parent`는 `page_id`를 받으므로, 실제 학생 명렬표는 3열 영역 바로 아래의 전폭 연결 뷰로 생성한다. 가운데 열에는 학생 명렬표 제목과 해당 DB로 가는 링크를 둔다.

MCP가 열 내부에 실제 연결 뷰를 배치하는 기능을 제공하면 학생 명렬표를 가운데 열에 둘 수 있다. 도구가 지원하지 않으면 Python과 같은 전폭 배치를 사용한다. **제목과 링크를 배치한 것만으로 가운데 열에 실제 학생 표가 생성되었다고 보고하지 않는다.**

빠른 동작은 실제 생성된 시간표, 수업 진도, 할 일, 아카이브, 수업자료로 이동하는 링크다. 클릭 한 번으로 새 업무를 만들거나 파일을 업로드하는 자동화 버튼은 아니다. `Share`의 공유 페이지·설문은 교사가 제공한 외부 링크이며, 링크를 입력한다고 공개 권한이나 설문이 자동 생성되지 않는다.

## 교사별 설정

`.local/config.json`의 `dashboard`는 선택 사항이다. 생략하면 빈 즐겨찾기·외부 링크와 기본 7교시를 사용한다. `periods`는 1~20 정수다. 실제 주소는 아래 빈 값에 입력하고 `.local/`에만 저장한다.

```json
{
  "dashboard": {
    "periods": 7,
    "bookmarks": [
      {"label": "업무 포털", "url": ""},
      {"label": "학교 자료실", "url": ""}
    ],
    "links": {
      "shared_page": "",
      "survey": ""
    }
  }
}
```

위 객체는 전체 설정 파일을 대체하지 않고 기존 학년도·교사·반·교과·모듈 설정에 추가한다. 외부 링크가 비어 있으면 클릭되지 않는 설정 안내를 표시한다. 원본에 있던 학교·기관·Drive·Notion 주소를 기본값으로 넣지 않는다.

교직원 연락망과 학교 계정 관리 DB는 각각 `modules.staff`, `modules.accounts`로 선택한다. 선택한 경우 기본 `School` 메뉴가 생성한 DB로 연결된다. 다른 교사가 저장소를 재사용할 때는 기존 네 가지 선택 기능과 함께 필요 여부를 확인한다. 이 저장소 제작 요청에서는 두 기능의 추가가 승인되어 예시 설정에서 활성화되어 있다.

학교 계정 관리에는 서비스명·접속 URL·계정 ID·관리 담당·보관 위치 링크를 기록한다. **비밀번호·복구 코드·토큰을 저장하는 필드는 만들지 않는다.** 필요한 경우 보관 위치에는 기존 비밀번호 관리 도구의 항목 링크만 넣는다. 계정 ID와 교내 연락처 역시 실제 자료이므로 공개 Git 예시에 넣지 않는다.

## 시간표 격자

상단 표의 열은 `교시 / 수업 시간 / 월 / 화 / 수 / 목 / 금`이다. 기본적으로 빈 1~7교시와 공동수업 안내 행을 만든다. 원본 화면의 시간·학급·교과를 그대로 넣지 않으며, 수업 시각은 학교에서 확인한 자료가 있을 때만 표시한다. 불러온 수업에 더 큰 교시가 있으면 최대 20교시까지 행을 늘리고, 다음 조회에 그 수업이 없다고 표의 행 자체를 다시 삭제하지 않는다.

시간표 DB가 원본이고 상단 격자는 특정 주를 보여 주는 표시용 표다. Python의 파일 가져오기와 컴시간 동기화가 적용되면, 같은 설치의 시간표 DB에서 해당 주 수업을 읽어 격자를 갱신한다. 일부 수업만 가져와도 그 입력만으로 기존 주간 셀을 전부 지우지 않는다.

- 컴시간 동기화는 조회해 반영한 주를 표시한다.
- 여러 주가 들어 있는 파일은 서울 기준 이번 주가 포함되어 있으면 그 주를, 그렇지 않으면 가장 나중 날짜가 속한 주를 표시한다.
- 표에 표시한 주간 날짜를 함께 확인한다. 단순히 날짜가 바뀌었다고 격자가 다음 주로 자동 전환되지는 않는다.
- `--watch`는 재조회 때 이번 주를 선택하므로 실행 중인 경우 새 주로 갱신할 수 있다. 프로세스가 꺼져 있으면 마지막 표시가 남는다.
- 교시 시각을 제공하지 않은 컴시간 자료는 수업의 날짜·교시·반·교과를 표시하며 시각은 추정하지 않는다.
- 격자는 월~금만 표시한다. 파일에 주말 수업이 있으면 시간표 DB와 캘린더에서 확인한다.

상단 격자를 수동 편집해도 원본 DB로 역전송되지는 않는다. 이후 시간표 동기화가 표시용 셀을 다시 갱신할 수 있으므로, 수업 수정은 원본 데이터와 정식 가져오기 경로에 반영한다. 마지막 `공동` 행은 별도 수동 메모 공간으로 보존하며 8교시와 같다고 가정하지 않는다. 공동수업 메모는 주가 바뀌어도 남으므로 직접 날짜를 확인한다.

격자 갱신은 원본 시간표 반영 뒤에 수행한다. 격자의 행·열을 직접 바꾸어 갱신이 중단되었다면 원본 시간표는 이미 반영되었을 수 있다. 기존 자료를 지우거나 설치 상태를 초기화하지 말고, 원본과 격자 구조를 확인한 뒤 같은 명령을 재실행한다. 응답 유실로 생성 여부가 불확실한 경우 [RECOVERY.md](RECOVERY.md)를 따른다.

MCP로 만든 홈은 Python 설치 상태와 섞지 않는다. Python 명령이 별도의 MCP 표까지 자동 갱신하는 것은 아니다. MCP 설치 담당 AI가 같은 원본 DB의 수업을 확인해 해당 주의 표를 갱신하고 결과를 검증한다.

## 기존 수첩을 사용하는 경우

새 템플릿은 새 설치의 기본값이다. 이전 설치 상태로 `install`을 실행하면 설계 차이를 감지해 중단하며 사용자 블록을 삭제하거나 홈을 새 배치로 덮어쓰지 않는다. 새 배치로 새 수첩을 만들려면 `--state .local/new-layout-state.json`처럼 별도 설치 상태를 사용한다. 새 수첩에는 기존 실기록이 자동 복사되지 않는다.

기존 수첩의 시간표 가져오기·동기화는 기존 설치 상태로 계속 사용할 수 있다. 이전 수첩에는 새 시간표 격자가 없으므로 그 상태로 새 홈까지 자동 생성·갱신하지 않는다.

기존 수첩 자체의 배치를 바꾸고 싶다면 수정할 페이지와 유지할 기록을 확인한 뒤 별도의 변경 작업으로 진행한다. 새 설치를 위해 기존 상태 파일을 삭제하는 방식은 사용하지 않는다.

## 원본에서 옮기지 않는 내용

참고 자료는 구조·비율·범주·색상의 근거로만 사용했다. 원본 HTML·PNG·CSV와 실제 시간표·회의 기록·학교 URL·워크스페이스 및 페이지 식별값은 공개 저장소에 포함하지 않는다. 기본 설치에 가상 예시를 넣는 것도 `demo`를 선택한 경우에만 수행한다.

[설치 확인 기준](ACCEPTANCE.md)에서 실제 화면·연결 뷰·링크·시간표 표시 주를 확인한다. 로컬 모의 테스트나 미리보기는 실제 Notion 생성 및 화면 검증과 구분해 보고한다.
