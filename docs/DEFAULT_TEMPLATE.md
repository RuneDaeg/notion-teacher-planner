# 네 페이지 교무수첩 기본 템플릿

기본 템플릿은 기존 Notion 안에 대시보드와 세 업무 페이지를 만든다. 사용자 제공 DESIGN.md와 네 화면 참고 이미지의 정보 구조를 반영하며, Notion 네이티브 페이지·콜아웃·연결 DB 보기를 사용하되 행·열·폭 비율·접기 위치는 아래 공통 배치 계약으로 고정한다. 색상·서체의 참고값과 구현 범위는 [DESIGN.md](../DESIGN.md)에 있다.

수첩은 학년도마다 한 권으로 운영한다. 해당 연도 3월부터 다음 해 2월까지 같은 수첩을 쓰고, 2학기가 되어도 기존 학생·상담·업무 기록을 이어 간다. 수업 진도의 `학기`는 필요한 기록에서 선택하며 1·2학기 보기로 구분할 수 있다.

데이터베이스·속성·원본 뷰는 `teacher_planner/blueprint.json` 버전 5, 논리 섹션은 `teacher_planner/dashboard.json` 버전 5, 실제 행·열 배치는 [`teacher_planner/layout_contract.json`](../teacher_planner/layout_contract.json)의 **`teacher-desk-layout-v1` / 버전 1**을 기준으로 한다. 섹션 목록을 세로로 나열하는 방식으로 이 배치 계약을 대신하지 않는다. `python -m teacher_planner plan --config .local/config.json --full`로 선택 모듈에 맞는 전체 구성을 확인한다.

## 필수 공통 배치 계약

네 핵심 페이지는 생성 직후 **전체 너비 켜기(`full_width=true`), 작은 텍스트 끄기(`small_text=false`)**를 기본값으로 적용한다. 이 값은 내부 배치 명세의 요구사항이며, 발견한 도구 명세에 없는 REST/MCP 요청 필드를 임의로 보내라는 뜻이 아니다. 사용하는 도구가 문서화된 설정을 제공하지 않으면 실제 Notion 페이지의 `•••` 메뉴에서 설정하고 상태를 확인한다. 페이지별로 확인하며 홈 설정을 하위 페이지에 자동 상속했다고 가정하지 않는다.

아래 순서는 위에서 아래, 한 행 안에서는 왼쪽에서 오른쪽 순서다. `40 / 60` 등의 숫자는 본문에서 열 사이 간격을 제외한 **상대 폭 비율**이다. 실제 픽셀·기기 화면·Notion 사이드바 폭까지 고정하지는 않는다. 제목과 표는 같은 열 안에 둔다. 제목만 다단으로 만들고 실제 DB를 그 아래 전폭으로 나열하면 불합격이다.

| 화면 | 위에서 아래로 고정할 배치 |
| --- | --- |
| 홈 | 공통 이동 링크와 브리핑 → 빠른 실행 4개 카드 **25 / 25 / 25 / 25** → 주간 시간표 **전폭** → 오늘 수업 관리용 목록 **닫힌 접기** → 중식 **40** / 우선순위 할 일·다가오는 마감 **60** → 출결 **50** / 상담 **50** → 진도 **55** / 평가 **45** → 주간·월간 캘린더 **전폭** → 문서 보관실·보조 페이지 링크 **하단** → 원본 링크 **닫힌 접기** |
| 학급 경영 & 학생 상담 | 공통 이동 링크와 안내 → 학생 명부 **전폭** → 출결 **50** / 제출물 **50** → 상담 **전폭** → 학부모 연락 **전폭** → 아침 메모 **50** / 오후 메모 **50** → 학교 업무 바로가기 |
| 교과 진도표 & 시간표 | 공통 이동 링크와 안내 → 공유 주간 시간표 **전폭** → 시간표 원본·관리용 목록 **닫힌 접기** → 수업 진도 **전폭** → 평가 **전폭** → 회의록 **50** / 수업·업무 자료 **50** |
| 학사 캘린더 & PARA | 공통 이동 링크와 안내 → 주간·월간·마감 캘린더 **전폭** → 다가오는 마감 **전폭** → PARA 안내 4열 **25 / 25 / 25 / 25** → 프로젝트 **전폭** → 담당 영역 **50** / 자료 **50** → 보관함 **전폭** → 원본 링크 **닫힌 접기** |

선택하지 않은 기능은 해당 섹션만 제거한다. 비어 있는 열·제목·접기를 남기지 않고 남은 열의 비율 합을 100으로 정규화한다. 예를 들어 출결을 선택하지 않은 홈에서는 상담이 전폭이 되고, 회의록을 선택하지 않은 교과 페이지에서는 자료가 전폭이 된다. 빠른 실행은 항상 생성하는 학생·상담·업무·수업 자료 등 실제 대상을 사용해 4개 카드를 유지한다. 기능을 선택하지 않았다고 순서나 남아 있는 쌍의 배치를 임의로 바꾸지 않는다. 정확한 조건과 비율은 계약에서 선택 설정으로 해석한 결과를 따른다.

하위 페이지를 만들며 생기는 페이지 링크와 원본 보관 페이지는 홈 상단에 방치하지 않는다. 업무 페이지의 공통 탐색은 위쪽에 유지하고, 실제 자식 페이지 블록·양식 모음·운영 자료·학생 기록은 아래 문서 보관실에 정리한다. DB·data source를 새로 복사하거나 페이지 소유 관계를 무작정 바꾸는 작업이 아니다.

```bash
python -m teacher_planner layout-plan --config .local/config.json
```

이 명령은 선택한 기능을 반영한 **목표 배치**를 읽기 전용으로 출력한다. 실제 Notion 상태나 설치 성공 증거가 아니다. MCP/UI 담당자는 이 결과의 행·열·섹션 위치를 그대로 구성하고 [설치 확인 기준](ACCEPTANCE.md)의 실제 재조회·화면 확인을 수행한다. 사용한 계약 ID·버전과 선택 설정을 비공개 설치 기록에 남긴다.

### 같은 배치를 출력하는 렌더러

로컬 실행이 가능하면 실제 생성된 섹션 조각을 비공개 JSON에 모아 같은 계약으로 조합한다. `render-layout`은 Notion에 쓰지 않으며, AI가 임의로 행·열을 바꾸는 것을 줄이기 위한 결정적 출력 도구다.

```bash
python -m teacher_planner render-layout --page home --sections .local/home-sections.json --output .local/home-layout.md
```

`--page`는 `home`, `classroom`, `teaching`, `planning` 중 하나다. 입력은 계약의 섹션 키를 해당 enhanced Markdown 문자열로 매핑한 JSON 객체이며, 빠른 실행·관찰 메모·학교 바로가기·PARA 카드 그룹은 문자열 배열로도 줄 수 있다. 문자열 섹션에는 필요한 제목과 **실제 기존 연결 DB 태그·페이지 링크·동기화 원본/참조**를 포함한다. 실제 생성 ID를 복사한 정확한 네이티브 조각을 사용하고 임의의 예시 URL로 바꾸지 않는다. 빠른 실행은 4개 카드이고 모르는 섹션·필수 섹션 누락·잘못된 카드 수는 오류다. 선택하지 않은 빈 섹션은 넣지 않는다.

새 설치는 각 섹션을 확인한 뒤 이 출력 구조로 구성한다. 기존 수첩은 먼저 모든 자식 페이지·DB·동기화 원본·사용자 본문을 목록화하고 [기존 수첩 수정 절차](UPDATES.md#기존-수첩을-공통-배치로-맞추기)를 따른다. 렌더러에 전달하지 않은 내용은 출력에 포함되지 않으므로 **출력 전체를 기존 페이지에 무조건 덮어쓰지 않는다**. 미분류 사용자 내용은 먼저 보존할 위치를 정하고, 기존 ID를 유지하는 이동·UI 편집으로 필요한 배치만 적용한다. 삭제 허용 옵션이나 초기화로 렌더링 차이를 해결하지 않는다. 렌더링 성공만으로 Notion 반영이나 UI 설정 완료를 보고하지 않는다. 쓰기 후 네이티브 블록 순서가 입력과 달라질 수 있으므로 실제 페이지를 다시 읽고 문제 구역만 부분 수정한다. 같은 전체 본문 교체를 반복하지 않으며 [쓰기 직후 재조회와 동기화 대상 ID 확인](INSTALL_WITH_MCP.md#배치-쓰기-직후-다시-읽기)을 따른다.

## 설치 경로와 완료 조건

MCP는 실제 도구에서 지원하는 열·접기·연결 DB 구문으로 위 구조를 만든다. 전체 너비, 열 비율, 닫힌 상태를 지원하지 않으면 Notion UI에서 보완한다. Python REST가 만드는 원본·관계·뷰·격자는 같은 기능 원본이지만 **열 안의 연결 DB 배치와 UI 설정까지 확인한 완성 화면으로 간주하지 않는다**. 지원하지 않는 중첩 배치는 MCP/UI로 마무리하며, 불가능하면 `기능 설치 확인 / 배치 확인 대기`로 정확히 보고한다. 세로 배치를 같은 템플릿으로 통과시키지 않는다.

설치 종료 전 실제 네 페이지를 다시 읽어 블록 부모·순서·열 위치·연결 DB를 확인하고, 실제 Notion 화면에서 네 페이지·전체 너비 메뉴·닫힌 접기와 폭을 확인한다. 계약을 읽어서 만든 계획이나 설치자가 직접 쓴 성공 표시만으로 검증하지 않는다. 증거와 스냅샷은 `.local/`에 보관하며 학생 정보가 담긴 화면을 공개 저장소에 넣지 않는다. [ACCEPTANCE.md](ACCEPTANCE.md)의 기능·배치·연동 결과를 각각 인계한다.

## 페이지별 구성

| 페이지 | 내용 |
| --- | --- |
| 대시보드 & 오늘 허브 | 오늘의 중식·양식 모음 링크, 오늘의 수업 · 주간 시간표, 우선 업무의 할 일·P1·완료·수집함 탭, 오늘 출결·상담, 반별 진도·확인 필요, 예정 평가, 주간·월간 캘린더, 다가오는 마감 |
| 학급 경영 & 학생 상담 | 학생 명렬표·갤러리·관찰 탭, 오늘 출결·미확인·전체 출결, 상담, 학부모 연락·제출물, 빈 아침·오후 관찰 메모 |
| 교과 진도표 & 시간표 | 요일×교시 주간 시간표 격자, 아래쪽의 원본 관리 영역, 반·교과·학기별 진도와 확인 필요 탭, 평가·회의, 수업 자료 보기 |
| 학사 캘린더 & PARA | 한 업무 원본의 주간·월간·마감 캘린더 탭, 다가오는 마감, P/A/R/Archive 콜아웃 열, 프로젝트 상태 보드·영역·자료·보관함 |

출결·제출물, 평가, 학부모 연락, 회의록, 교직원 연락망, 학교 계정 관리는 선택한 경우에만 표와 메뉴를 만든다. 기본 9개, 모두 선택하면 16개 원본 DB를 사용한다. 추가 페이지는 같은 원본을 연결하며 학생·수업·일정을 새 DB로 복사하지 않는다. 모두 선택한 계획에는 원본 뷰 59개와 연결 뷰 46개, 총 105개 뷰가 있다. 46개 연결 뷰는 네 핵심 페이지의 24개 연결 DB 블록 안에 탭으로 들어간다. 별도로 원본을 보관할 `운영 자료`·`학생 기록` 페이지를 만든다. 연결 블록 수를 원본 DB 수로 세지 않는다. 급식 표시와 양식 모음은 기존 네 핵심 페이지·DB·뷰 수를 바꾸지 않는다. 양식 모음과 선택한 양식은 별도 보조 페이지다.

네 페이지에는 같은 이동 링크를 두고 현재 페이지에서 다른 업무 페이지로 바로 이동할 수 있게 한다. 실제 하위 페이지는 Notion 기본 사이드바에서도 탐색한다. 고정 240px의 별도 사이드바를 만드는 기능은 아니다. 링크에는 이번 설치에서 만든 페이지 ID만 사용한다.

## 표와 보기 탭

학생·할 일·진도·캘린더의 여러 화면은 같은 원본의 보기 탭이다. 같은 페이지에서 탭을 공유하도록 지정한 뷰는 부모 database ID도 공유한다. 다른 페이지에 있는 연결 DB 블록은 서로 다른 ID를 가져도 같은 data source ID를 사용하므로 원본 기록은 하나다.

대시보드의 `주간 캘린더 / 월간 캘린더`는 하나의 연결 DB에 속하며 둘 다 업무·일정의 `일정` 속성을 사용한다. 학사 캘린더 & PARA 페이지에서는 같은 방식으로 주간·월간 탭을 만들고, 같은 원본의 `마감` 속성을 쓰는 마감 탭을 추가한다. 주간·월간 표시 범위는 각각 week/month다. 선택형 [NEIS 공개 학사일정](SCHOOL_CALENDAR.md)도 같은 업무·일정 원본의 종일 일정으로 들어오며 DB·탭 수를 늘리지 않는다. 홈과 교과 페이지의 기본 시간표는 같은 교사 시간표 원본과 같은 표시 주간을 사용하는 요일×교시 격자다. 오늘 수업만 보여 주는 필터 목록은 관리용으로 유지한다. 파일·컴시간 가져오기는 교사 시간표 원본에 반영한 뒤 격자를 갱신하며 업무·일정·To-Do·학사 캘린더에 수업을 추가하지 않는다.

표와 보기 탭의 최종 위치는 공통 배치 계약을 따른다. Python REST가 연결 DB를 일단 페이지 직속으로 생성한 경우에도 이는 기능 설치 단계다. 지원되는 MCP/UI로 계약의 열·접기 안에 배치한 뒤 검증해야 배치까지 완료할 수 있다. 제목·링크만 놓고 실제 표가 만들어졌다고 보고하지 않는다.

업무 완료는 원본의 상태 편집, 출결 확인은 확인 체크박스, 진도는 실제 계획·완료 차시로 관리한다. 빈 원본에 요약 숫자·출석률·평균 진도율을 임의로 표시하지 않는다. 레코드의 진도율·채점률·마감 수식을 사용하고, 별도 집계가 필요하면 지원되는 Notion UI의 계산을 설정한 뒤 확인한다.

## 빠른 입력과 메모

빠른 입력 링크로 학생·상담·업무·시간표 등 대상 DB를 열고 Notion의 `새로 만들기`로 기록한다. 링크를 자동 생성 버튼으로 소개하지 않는다. 자료는 원문 URL과 자료 DB를 통해 관리하며, 구현하지 않은 파일 업로드 자동화나 외부 알림 기능을 안내하지 않는다.

학급 페이지의 아침·오후 관찰 콜아웃은 처음에 비어 있는 수동 메모 공간이다. 날짜가 지나도 내용이 자동 초기화되거나 학생 DB로 복사되지 않는다. 기록할 날짜를 함께 쓰고, 지속 추적할 학생 기록은 해당 학생의 관찰·상담 원본에 남긴다.

## 오늘 중식과 양식 모음

홈의 `오늘의 중식` 콜아웃은 NEIS 공개 식단 중 중식 메뉴·열량을 보여 주는 표시 영역이다. 처음에는 연결 안내를 두고, 조회 후 학교·기준 날짜·확인 시각·알레르기 번호·출처를 유지한다. 조식·석식·원산지·영양정보는 원본에 보존하고 홈에서는 생략한다. 중식이 없으면 공개 중식 정보 없음, 오류면 이전 표시 유지로 처리한다. 다른 식사로 대체하지 않으며 기존 보관 기록은 바꾸지 않는다. 업무·일정·시간표·To-Do에는 급식 행을 넣지 않는다. 실행 중 주기 갱신과 날짜 변경은 [MEALS.md](MEALS.md)를 따른다.

`양식 모음`은 현재 모듈·담임 설정에서 선택한 빈 기록 양식의 보조 페이지다. 본문을 복사하거나 기록용 페이지로 복제해 사용하며 네이티브 DB 템플릿 자동 등록으로 소개하지 않는다. `forms` 선택과 사용 순서는 [FORMS.md](FORMS.md)에 있다.

새 설치에 포함되며 기존 수첩에는 `setup-extras`로 이 추가 영역만 설치할 수 있다. 기존 페이지·뷰·기록을 재배치하거나 복사하지 않는다. 추가 설치 자체가 학교 급식 조회를 시작하지는 않는다. 원래 config·state를 사용하며 이미 설치한 뒤 `forms` 선택을 바꾸는 자동 마이그레이션은 제공하지 않는다.

## 교사별 설정

`.local/config.json`의 `dashboard`는 선택 사항이다. `periods`는 시간표 격자의 기본 교시 수이며 1~20 정수다. 기본값은 7이며 학교의 교시 수에 맞게 지정한다. 실제 주소는 아래 빈 값에 입력하고 `.local/`에만 저장한다.

```json
{
  "dashboard": {
    "periods": 7,
    "bookmarks": [
      {"label": "업무 포털", "url": ""},
      {"label": "학교 자료실", "url": ""}
    ],
    "links": {"shared_page": "", "survey": "", "neis": "", "edufine": ""}
  }
}
```

위 항목은 기존 학년도·교사·반·교과·모듈 설정에 추가한다. 새 설치에는 수첩 전체의 학기를 지정하지 않으며 루트 제목은 `{academic_year}학년도 · {title}`이다. 기존 설정의 `semester`는 호환성을 위해 그대로 보존한다. 비어 있는 링크에는 설정 안내를 표시하며 원본 학교 주소를 기본값으로 넣지 않는다. 공유 페이지·설문 링크를 입력해도 공개 권한이나 설문을 자동 생성하지 않는다. `neis`와 `edufine`은 교사가 입력한 URL을 여는 바로가기이며 자동 로그인·조회·쓰기를 제공하지 않는다. 공개 학사일정 조회는 NEIS API 인증키와 학교 코드를 사용하는 별도 명령으로 연결한다. 교직원 연락망과 학교 계정 DB는 `modules.staff`, `modules.accounts`로 선택한다. 학교 계정에는 서비스 URL·계정 ID·관리 담당·외부 보관 위치를 기록하며 비밀번호·복구 코드·토큰을 넣지 않는다.

## 요일×교시 주간 시간표

홈과 교과 진도표 & 시간표 페이지의 기본 시간표는 `교시 / 수업 시간 / 월 / 화 / 수 / 목 / 금` 열을 갖는 표시용 격자다. 두 페이지는 같은 교사 시간표 원본과 같은 표시 주간을 사용한다. 교시와 수업 시간은 세로로, 월~금은 가로로 읽는다. 기본 7교시와 공동 메모 행으로 시작하며 불러온 수업에 맞춰 최대 20교시까지 확장한다. 교시 시각은 학교에서 확인한 경우에만 표시하고 추정하지 않는다.

새 설치에서는 교과 페이지에 표시 주간 안내·격자·동기화 안내를 담은 원본 동기화 블록(`synced_block`)을 만들고 홈의 `오늘의 수업 · 주간 시간표`에 그 블록을 참조한다. Python REST도 이 구조를 사용한다. 격자와 표시 주간 안내의 ID는 각각 하나만 저장하며, 가져오기·동기화는 이 자식 블록들을 갱신한다. 두 페이지에 별도 수업 행이나 표 사본을 만들지 않는다.

교사 시간표 DB가 수업의 원본이다. 원본 DB의 목록형 관리 보기는 주간 격자 아래 `시간표 원본 · 관리용`으로 구분한다. 홈의 관리 목록도 주간표 아래로 분리한다. 오늘 수업 목록은 `오늘 수업 원본 · 목록으로 확인` 제목의 닫힌 접기 영역에, 교과 원본 목록은 `시간표 원본 · 관리용` 제목의 닫힌 접기 영역에 보존한다. Python REST가 관리용 뷰를 직접 배치한 상태는 중간 결과이며 MCP/UI에서 접기 구조를 마무리하기 전에는 배치 검증을 통과하지 못한다. `오늘 수업` 목록은 같은 원본에 `오늘 수업=true` 필터를 적용한 관리용 보기로 유지한다. 기본·오늘·변경 관리 보기의 핵심 열은 `이름·수업일·교시·학급·교과·교실·상태`다. 원본을 접거나 숨기는 것은 화면 정리이며 접근 권한을 제한하지 않는다.

Python의 파일 가져오기·컴시간 동기화는 날짜가 검증된 수업을 원본 DB에 반영한 뒤 해당 주의 저장된 수업을 다시 읽어 홈과 교과 페이지 격자 및 표시 주간을 일치시킨다. 일부 수업만 입력해도 원격에 남아 있는 수업을 임의로 지우지 않고 늘어난 교시 행도 자동 삭제하지 않는다. 실제 학교와 연결하지 않은 설치는 빈 격자로 시작한다. 예시를 요청받아 수업을 넣었다면 가상 예시임을 표시하고 실제 컴시간 조회 결과로 안내하지 않는다.

- 컴시간은 조회해 반영한 주를 표시한다.
- 여러 주가 든 파일은 서울 기준 이번 주가 포함되면 그 주를, 없으면 가장 나중 날짜가 속한 주를 표시한다.
- 표에 주간 날짜를 함께 표시한다. 프로세스가 종료되면 마지막 표시가 남으며 자정이나 월요일에 스스로 바뀌지 않는다.
- `--watch`가 실행 중이면 재조회 때 이번 주를 선택한다. 실제 수업 시각이 없으면 날짜·교시만 사용한다.
- 격자는 월~금만 표시한다. 주말 수업은 교사 시간표 원본에서 확인한다.

격자의 수동 편집은 원본 DB로 역전송되지 않는다. 공유 표의 수동 변경은 두 페이지의 격자에 함께 표시될 수 있으므로 원본 수업 데이터 갱신과 구분한다. 수업 데이터는 교사 시간표 DB에서 기록하거나 파일·컴시간으로 가져온다. 동기화가 관리하는 셀은 다음 반영 때 갱신될 수 있다. 마지막 `공동` 행은 별도 수동 메모로 보존하며 8교시로 해석하지 않는다. 그 메모는 주가 바뀌어도 남으므로 직접 날짜를 확인한다.

격자 갱신은 원본 시간표 반영 뒤에 수행한다. 격자 구조를 바꾸어 갱신이 중단되었다면 원본은 이미 반영되었을 수 있으므로 자료를 지우지 말고 구조를 확인해 재실행한다. 응답 유실은 [RECOVERY.md](RECOVERY.md)를 따른다. MCP로 만든 표시용 격자는 Python 상태와 자동으로 연결되지 않으며, MCP 담당자가 같은 원본을 읽어 홈과 교과 페이지의 격자 및 표시 주간이 일치하도록 갱신·검증한다.

## 기존 수첩과 검증 범위

제목에 `1학기` 또는 `2학기`가 있는 기존 수첩도 같은 학년도 동안 이어 쓴다. 제목 변경을 요청받으면 기존 페이지 제목만 바꾼다. 이는 DB 구조 변경이 아니므로 원래 config·state와 `semester` 값을 유지하고, DB·기록을 복제하거나 설치 상태를 초기화하지 않는다. 다음 학년도에는 이전 수첩을 보존하고 새 설정과 별도 상태 경로로 새 수첩을 준비한다.

대시보드 버전 5는 새 설치의 기본값이다. 이전 설치 상태에서 `install`을 실행하면 설계 차이를 감지해 중단하고 기존 페이지·블록을 유지한다. 새 배치는 새 설치의 기본값이며 기존 수첩은 요청된 범위에서 기존 ID·기록을 보존하는 배치 수정으로 맞출 수 있다. 이 작업을 위해 상태를 지우거나 새 수첩을 재설치하지 않는다. 실제로 별도 수첩이 필요한 요청만 새 상태 경로를 사용하며 기존 자료를 자동 복사하지 않는다. 이전 수첩의 시간표 동기화와 소유한 격자 갱신은 기존 경로로 계속 사용할 수 있다.

이전 버전이 업무·일정에 복사한 수업과 기존 관계는 그대로 남는다. 동기화가 이를 자동 정리하지 않으므로 필요하면 대상 기록을 확인한 별도 작업으로 정리한다.

급식 영역·양식 모음만 추가할 때는 기존 완료 상태에 `setup-extras`를 사용한다. 네 페이지 전체를 새 배치로 바꾸는 작업과 구분한다.

기존 수첩의 배치 변경은 대상과 유지할 기록을 확인한 별도 작업으로 진행한다. 상태 파일을 삭제해 새 배치를 강제로 적용하지 않는다. 원본 참고의 이름·사진·전화번호·학교 URL·실제 기록은 배포하지 않는다.

출결은 보조 기록이며 공식 NEIS 출결·학적에 자동 반영하지 않는다. 공개 학사일정은 API 조회 결과를 기존 Notion 캘린더로 가져온다. 컴시간은 선택형 주기 조회이고 실시간 푸시·클라우드 상시 실행·보호자 자동 발송은 제공하지 않는다. 실제 생성·수정 결과와 [ACCEPTANCE.md](ACCEPTANCE.md)를 확인하며, 미리보기·모의 테스트를 실제 Notion 검증으로 보고하지 않는다.
