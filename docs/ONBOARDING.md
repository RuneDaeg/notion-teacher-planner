# 공통 설치 질문지

질문지 버전: `2` · 기준일: `2026-10-01`

어떤 AI를 사용하든 새 교무수첩의 설정을 같은 질문으로 받기 위한 원본이다. 질문 문구·선택지·순서는 이 문서에서 관리한다. [START_HERE.md](../START_HERE.md)는 실행 절차를, 이 문서는 입력 절차를 정한다. 사용자의 명시적인 요청과 이미 받은 답을 우선한다.

[5단계 웹 질문지](https://notion-teacher-planner.notion-teacher-planner-cloudflare.workers.dev/setup)는 이 질문지의 Q01·Q02, Q03·Q04, Q05·Q06, Q07·Q08, Q09·Q10을 순서대로 보여 준다. 조건부 질문도 해당 질문 뒤에 표시한다. 브라우저가 답변으로 AI 설치 요청문을 만들며, 실제 설치와 연동은 요청문을 받은 AI가 실행 능력과 필요한 값을 확인한 뒤 진행한다. 웹 사용법·임시 저장 범위는 [WEB_SETUP.md](WEB_SETUP.md)에 있다.

## AI가 질문하는 방법

1. 먼저 대화와 해당 교사의 비공개 설치 기록에서 답을 찾는다. 다른 교사·제작자 예시의 답을 재사용하지 않는다. 기존 수첩 수정 요청이면 새 설치 질문을 시작하지 말고 [수정 안내](ITERATIVE_EDITING.md)·[업데이트 안내](UPDATES.md)를 따른다.
2. Notion 쓰기 도구 또는 로컬 설치 실행 가능 여부를 먼저 확인한다. 도구가 없으면 설정 준비까지만 가능하다고 알려 준다. 사용자에게 AI 이름이나 모델명을 물어 실행 능력을 추측하지 않는다.
3. 아래 질문의 **ID·순서·질문 문구·선택지를 유지**한다. 한 번에 아직 답하지 않은 질문 2~3개만 제시한다. 선택지의 번호도 유지한다. 사용자가 다른 언어를 요청하면 같은 의미로 번역할 수 있다.
4. `Q07-C` 같은 추가 질문은 조건을 만족할 때 해당 기본 질문 바로 뒤에 한다. 조건에 맞지 않는 질문은 건너뛰고 번호를 다시 매기지 않는다. 한 질문의 일부만 답했다면 남은 항목만 원문 표현으로 묻는다.
5. 자유로운 문장 답변도 받는다. `①·③`은 해당 두 선택만, `모두`는 **그 질문에 표시한 선택 범위**만 뜻한다. 모순되거나 식별이 모호하면 해당 항목만 구체적으로 확인한다. 추천 표시나 응답 대기를 동의로 간주하지 않는다.
6. 질문 상태를 `확정 / 미응답 / 나중에 / 해당 없음`으로 구분한다. 이미 확정된 답은 재질문하지 않는다. 사용자가 바꾸면 최신 답을 적용하고 달라진 조건부 항목만 확인한다.
7. 필요한 답이 모이면 학교·학년도·반·생성 위치·선택 기능·연동 범위를 짧게 보여 주고 요청받은 생성을 진행한다. 이미 생성 요청과 설정이 명확하다면 별도의 전체 승인 질문을 추가하지 않는다. OAuth 권한 부여처럼 사용자가 직접 해야 하는 단계는 실제 연결 시 안내한다.

첫 안내 문구:

> 공통 질문지에 따라 필요한 설정을 2~3개씩 여쭙겠습니다. 이미 알려주신 내용은 다시 묻지 않습니다. 선택 항목은 ‘나중에’라고 답해도 됩니다.

질문 원문을 임의의 새 설문으로 요약하거나 문서에 없는 기능을 기본 선택으로 추가하지 않는다. 추가 요구가 있으면 해당 요구에 필요한 확인만 별도로 한다. 이 문서는 AI의 진행 지침이며, 모든 AI가 이를 준수하도록 기술적으로 강제하는 기능은 아니다.

## 고정 질문

### Q01 · 학교

> 어느 학교에서 사용하시나요? 지역, 학교명, 학교급을 알려주세요. 예: 충남 / 예시고등학교 / 고등학교. 학교 연동을 나중에 하려면 지역·학교명은 ‘나중에’라고 답해도 됩니다.

학교명·지역은 학교 식별용이다. 식별 코드가 필요하면 Q08의 연동 경로에서 AI가 공식 조회 결과로 확인한다. 동명이거나 조회되지 않으면 그때 후보 학교의 지역·주소로 구분한다. NEIS 코드와 컴시간 코드를 혼용하지 않는다.

### Q02 · 학년도와 표시 이름

> 몇 학년도 수첩을 만들까요? 화면에 표시할 선생님 이름이나 별칭도 알려주세요. 이름을 쓰지 않으려면 ‘교사’로 표시합니다.

학년도는 현재 날짜로 단정하지 않는다. **한 학년도(3월~다음 해 2월)에 수첩 하나**를 만들며 학기를 설치 필수 질문으로 받지 않는다. 루트 제목은 `{학년도}학년도 · {수첩 제목}`이다. 2학기에도 같은 수첩을 사용하며, 필요한 수업 진도 기록의 `학기` 속성과 1·2학기 보기는 유지한다. 교사 실명은 필수가 아니다.

### Q03 · 담당 수업과 담임

> 담당 교과와 학년·반을 알려주세요. 담임이면 담임 학급도 함께 적어주세요. 예: 통합과학 / 1학년 1~3반 / 1학년 2반 담임. 담임이 아니면 ‘비담임’이라고 적어주세요.

교과나 담당 반이 아직 정해지지 않았다는 답을 가상의 교과·반으로 채우지 않는다. 현재 Python 설치에는 교과와 학급이 각각 최소 하나 필요하므로, 해당 값이 없으면 나머지 설정을 준비하고 설치를 대기한다. 반별 교과가 다른 경우 사용자가 준 구분을 보존하고 시간표 반영 전에 대조한다.

### Q04 · Notion 생성 위치

> 새 교무수첩을 만들 상위 Notion 페이지 링크를 알려주세요. 개인용으로 쓸지, 지정한 교직원과 함께 쓸지도 알려주세요. 페이지를 아직 정하지 않았다면 ‘위치 선택 도움’이라고 답해주세요.

이미 개인 페이지에 새로 만들기를 요청했고 도구가 그 위치를 지원하면 링크를 다시 요구하지 않는다. Python 경로에는 접근 가능한 상위 일반 페이지가 필요하므로 위치 선택을 돕는다. 공유 의향은 공유 권한을 임의로 바꾸는 지시가 아니다. 실제 접근 범위를 확인하고, 학생 기록을 담은 전체 수첩을 공개하지 않는다. 필터·접기·숨긴 보기를 접근 제한으로 설명하지 않는다.

### Q05 · 추가 기능

> 기본 구성은 학생 명단·상담 기록·업무/할 일·주간/월간 캘린더·시간표·수업 진도·PARA입니다. 추가할 기능의 번호를 골라주세요. 여러 개 또는 ‘모두’, ‘없음’, ‘나중에’로 답할 수 있습니다.
>
> ① 출결·제출물 체크 ② 평가·채점 현황 ③ 학부모 연락 기록 ④ 회의록·결정 사항 ⑤ 교직원 연락망 ⑥ 학교 계정 관리

학교 계정 관리는 서비스 주소·계정 ID·담당자·외부 비밀번호 관리 도구의 위치만 기록한다. 비밀번호·복구 코드·토큰을 입력받는 표가 아니다.

### Q06 · 자주 쓰는 양식

> 미리 준비할 빈 기록 양식을 골라주세요. 여러 개 또는 ‘사용 가능한 양식 모두’, ‘없음’, ‘나중에’로 답할 수 있습니다.
>
> ① 학생 상담일지 ② 학부모 연락·상담 기록 ③ 회의록·결정 및 후속 조치 ④ 수업 계획·성찰 ⑤ 평가 계획·채점 기록 ⑥ 조회·종례 전달사항

선택지는 같은 번호로 모두 보여 주되, Q05·담임 여부에 따라 사용할 수 없는 항목에는 조건을 덧붙인다. ②는 학부모 연락, ③은 회의록, ⑤는 평가·채점 기능이 필요하고 ⑥은 담임 학급이 있어야 한다. `사용 가능한 양식 모두`는 현재 선택한 기능·담임 설정에서 가능한 것만 뜻한다.

조건에 맞지 않는 양식을 명시적으로 고른 경우에만 `Q06-D`를 묻는다:

> 선택하신 {양식 이름}에는 {필요한 기능 또는 담임 학급}이 필요합니다. ① 해당 설정을 추가하기 ② 이 양식은 나중에 준비하기 중 골라주세요.

`{…}`에는 실제 충돌 항목만 넣는다. ①을 고르면 필요한 설정을 확인한다. 양식을 선택했다는 이유만으로 모듈을 켜거나 담임으로 바꾸지 않는다.

하나 이상의 사용 가능한 양식을 고른 경우에만 `Q06-N`을 묻는다:

> 양식을 어떻게 사용할까요? ① Notion의 ‘새로 만들기’ 메뉴에 등록 ② 본문을 복사해서 쓰는 ‘양식 모음’만 준비

①은 [FORMS.md](FORMS.md)의 실제 UI 등록까지 요청한 것으로 기록한다. 도구가 UI 등록을 지원하지 않으면 가능한 복사용 양식을 준비하고 메뉴 등록이 남았음을 명시한다. 특정 학생·날짜를 미리 채우거나 기본·반복 템플릿으로 설정하지 않는다.

### Q07 · 시간표

> 시간표는 어떻게 준비할까요? ① 컴시간 웹에서 가져오기 ② 날짜가 포함된 CSV/JSON 파일에서 가져오기 ③ 빈 표로 시작하고 나중에 입력하기

①일 때만 `Q07-C`를 묻는다:

> 컴시간 학교 코드와 선생님 번호를 알려주세요. 모르면 ‘확인 도움’이라고 답해주세요.

컴시간 비공식 웹 조회라는 점과 [COMCIGAN.md](COMCIGAN.md)의 조회·반영 절차를 설명한다. 번호를 추정하지 않는다. 도움을 요청하면 공개적으로 확인 가능한 경로를 안내하거나 허용된 조회를 사용하고, 확인되지 않으면 연동을 대기한다. 선택한 학교·교사·주간·담당 수업이 맞는지 조회 결과로 검증한다. 현재 웹 어댑터는 월~금·1~3학년·1~8교시를 해석하므로 범위 밖에는 파일 경로를 안내한다. 현재 클라우드의 하루 한 번 갱신에는 컴시간이 포함되지 않는다.

②일 때만 `Q07-F`를 묻는다:

> 날짜·교시·시작/종료 시각·교과·학급·교실·상태가 들어 있는 시간표 CSV/JSON 파일을 제공해주세요. 아직 준비되지 않았다면 ‘나중에’라고 답해주세요.

파일 제공은 사용하는 AI의 일반 첨부 기능을 안내한다. 텍스트만 받는 질문 도구로 파일 첨부를 요구하지 않는다. [파일의 정규 형식](COMCIGAN.md#파일의-정규-형식)의 `date`, `period`, `start`, `end`, `class_name`, `subject`, `room`, `status` 여덟 필드를 검증한다. 파일 방식은 실제 시작·종료 시각이 필요하며, 시각을 모르면 가져오기를 대기한다. 교실 값은 빈 문자열을 허용하지만 필드 자체를 생략하지 않는다.

표의 교시 수나 시각이 아직 확인되지 않았다면 `Q07-T`를 묻는다:

> 하루 몇 교시까지 표시할까요? 학교의 교시별 시작·종료 시각도 있으면 알려주세요. 교시 수는 ‘기본 7교시’, 시각은 ‘나중에’로 답해도 됩니다.

컴시간·빈 표 방식에서 시각이 없는 경우 시간을 추정하지 않고 교시·날짜만 표시한다. 파일에 검증된 시각이 있다면 재질문하지 않는다. 홈과 교과 페이지는 같은 주간표를 사용하고, 수업을 업무·일정·To-Do에 복사하지 않는다.

### Q08 · 중식과 학사일정

> 학교 중식과 학사일정은 어떻게 가져올까요?
>
> ① 둘 모두 하루 한 번 자동 갱신 ② 필요할 때 중식만 가져오기 ③ 필요할 때 학사일정만 가져오기 ④ 필요할 때 둘 모두 가져오기 ⑤ 나중에 연결하기

①은 운영 중인 공용 서비스와 Notion OAuth 연결을 사용하는 선택이다. 현재 서비스는 중식과 학사일정을 함께 처리하므로 한쪽만 자동 갱신한다고 약속하지 않는다. 교사는 서버 계정·NEIS 키를 따로 등록하지 않는다. 운영자가 배포·확인한 서비스와 등록 가능 여부를 확인하고, 이용할 수 없으면 연결 대기로 남긴다. 사용자의 요청 없이 대신 서버를 새로 만들거나 유료 서비스를 가입하지 않는다.

②~④는 요청할 때 조회·반영하는 경로이며 자동 예약을 만들지 않는다. 해당 AI의 실행 환경과 안전한 자격 증명 설정을 확인하고 [급식](MEALS.md)·[학사일정](SCHOOL_CALENDAR.md) 절차를 따른다. 조회 수단이나 키가 없으면 가능한 준비까지만 수행하고 제한을 설명한다. 키 없는 샘플 몇 건을 전체 학사일정으로 사용하지 않는다.

①~④를 선택했는데 Q01에서 학교를 미뤘다면 Q01의 지역·학교명만 이어서 묻는다. 학교 코드 확인에 성공하면 비공개 기록에 저장해 다시 입력받지 않는다. 학교 코드가 같아 보인다는 이유로 컴시간 코드를 재사용하지 않는다.

홈에는 중식만 표시한다. 주간·월간 캘린더는 같은 원본 DB의 보기이며, 연속된 같은 이름의 학교 행사는 검증된 기간으로 묶는다. 기본 수첩의 급식 안내 영역 생성과 실제 조회·예약 활성화는 별개다.

### Q09 · 가상 예시

> 처음에는 어떤 기록으로 시작할까요? ① 빈 수첩으로 시작하기(추천) ② 사용법을 볼 수 있도록 가상 예시 기록 넣기

①은 `demo=false`, ②는 `demo=true`다. ②도 실제 학생 정보나 제작자의 기록을 복사하는 요청은 아니다. 가상 기록임을 표시한다. 학생 명단·상담 내용 업로드를 설치의 필수 질문으로 추가하지 않는다.

### Q10 · 제목과 바로가기

> 수첩 제목이나 자주 쓰는 업무 사이트 바로가기를 지정할까요? 제목은 기본 ‘교무수첩 데스크’를 쓸 수 있습니다. 바로가기는 이름과 주소를 적거나 ‘나중에’라고 답해주세요.

사용자가 지정한 공유 페이지·설문·NEIS·에듀파인·업무 포털 링크를 저장할 수 있다. 링크 설정을 설문 생성·공개 공유·자동 로그인·공식 NEIS 쓰기로 확대하지 않는다.

## 답변을 설치 설정에 옮기기

AI가 아래 규칙으로 옮긴 뒤 기존 설치 계획 도구로 검증한다. 웹 질문지는 `cloud/web/setup-model.mjs`의 정해진 규칙으로 질문 ID·답변·선택 범위를 포함한 요청문을 브라우저에서 생성한다. 서버나 LLM API에 답변을 보내지 않으며, 웹 요청문 자체는 설치 설정의 최종 검증이나 Notion 쓰기를 수행하지 않는다.

| 답변 | 설정·비공개 기록 |
| --- | --- |
| Q01 | `school_level`; 지역·학교명·공식 조회로 확인한 NEIS 코드는 별도 학교/연동 기록 |
| Q02 | `academic_year`, `teacher`; 새 설치 config에는 `semester`를 넣지 않음 |
| Q03 | `subjects`; `classes[]`의 `name`, `grade`, `class_name`, `homeroom` |
| Q04 | 지정한 상위 페이지와 공유 범위; Python은 `NOTION_PARENT_PAGE_ID`, MCP는 해당 도구의 부모 지정 |
| Q05 ①~⑥ | 각각 `modules.attendance`, `assessment`, `contact`, `meeting`, `staff`, `accounts` |
| Q06 ①~⑥ | 각각 `forms`의 `counseling`, `guardian`, `meeting`, `lesson`, `assessment`, `homeroom`; 메뉴 등록 요청은 별도 작업 기록 |
| Q07 | 시간표 가져오기 방식·검증한 컴시간 코드/교사 번호·파일 위치는 별도 연동 기록; 교시 수는 `dashboard.periods`, 시각은 [COMCIGAN.md](COMCIGAN.md)의 별도 시각 파일 |
| Q08 | 연동 범위·수동/예약 선택과 준비/활성 상태를 별도로 기록; 실제 생성 ID로 클라우드 manifest 구성 |
| Q09 | `demo` |
| Q10 | `title`, `dashboard.bookmarks`, `dashboard.links` |

- **새 설치**의 `modules`에는 여섯 키를 모두 참/거짓으로 적고 `forms`도 명시한다. 선택하지 않은 모듈은 `false`, 양식 없음은 `[]`다. `config.example.json`의 모든 모듈 `true`와 `forms` 생략 시의 자동 선택을 교사의 답으로 사용하지 않는다.
- 이 한국 학교용 질문지에서는 `timezone`을 `Asia/Seoul`로 명시하고 설정 요약에 표시한다. 사용자가 이미 다른 IANA 시간대를 지정했다면 보존한다. 다만 컴시간 연동은 `Asia/Seoul`만 지원하므로 해당 조합에서는 시간대 또는 시간표 경로를 확인하고 임의로 덮어쓰지 않는다.
- `나중에`인 선택 기능은 이번 설치에서 비활성으로 두고 연동도 시작하지 않는다. 미응답은 동의가 아니다. 학년도·담당 교과·학급·생성 위치처럼 실제 생성에 필요한 값이 비어 있으면 그 값만 확인한다.
- 교사가 ‘나머지는 기본으로’라고 요청하면 제목 `교무수첩 데스크`, 표시 이름 `교사`, 한국 시간 `Asia/Seoul`, 격자 7교시, 미선택 모듈 `false`, 미선택 양식 `[]`, 가상 기록 없음, 미선택 연동 대기, 바로가기 없음으로 정한다. 실제 학교·교사 번호·수업 시각·교과·학급·학년도·생성 위치는 만들어내지 않는다. 이미 명시한 선택은 보존한다.
- 반별로 담당 교과가 다르다면 별도 답변 기록에 구분을 보존한다. 현재 Python 초기 학급 생성은 전체 `subjects`를 각 학급의 담당 교과로 넣으므로, 이를 반별 교과 검증 완료로 보고하지 않는다. 후속 보정은 실제 대상과 답변을 대조한다.
- 처음부터 파일·컴시간 가져오기를 선택했다면 가능한 조회·파일 검증을 **수첩 설치 전에** 진행해 Q03의 교과·반과 대조한다. 설치 후 config 지문 불일치를 피하려고 설정을 임의로 바꾸거나 상태를 초기화하지 않는다. 자료가 없어 연동을 미룬 경우에는 확인된 교과·반으로 설치하고 그 보류 상태를 남긴다.
- 로컬 실행이 가능하면 `python -m teacher_planner plan --config .local/config.json --full`로 선택 DB·양식·보기 구성을 확인한다. 기존 설치에 답변을 다시 적용하려고 원래 config나 설치 상태를 덮어쓰지 않는다.

## 재질문을 막는 답변 기록

파일 저장이 가능한 AI는 `.local/onboarding.md`에 질문지 버전, 각 질문 ID, 상태, 확정값, 답변 근거(이번 답변/기존 사용자 답/검증된 조회), 보류 이유를 남긴다. 수정 시 최신 답과 변경 이유를 반영한다. 로컬 파일을 다룰 수 없다면 같은 구조의 짧은 답변 요약을 현재 비공개 대화에 남긴다. 다른 AI가 이 대화나 파일을 자동으로 공유받는다고 가정하지 않는다.

학교 설정과 설치 대상만 기록하고 토큰·API 키·비밀번호·실제 학생 명단·상담 내용을 질문지 답변에 넣지 않는다. 답변 파일·config·설치 상태는 Git에 올리지 않는다. 공개 질문지에는 특정 교사의 실제 학교 코드·Notion ID를 기본값으로 넣지 않는다.

웹 화면의 초안은 현재 탭의 `sessionStorage`에 임시 저장하고 초기화할 수 있다. 버전 1 초안도 학교·학년도·기능 등 나머지 답변을 이어받으며, 학기 응답만 새 요청문에서 제외한다. 버전 2로 전환되었다는 안내를 표시한다. **이 변환은 웹 설문 초안에만 적용**하며 이미 설치한 수첩의 config·state에서 `semester`를 삭제하는 절차가 아니다. 기존 설치 상태는 그대로 보존한다. 다른 기기나 AI로 자동 전달되지 않으므로, 교사가 요청문을 복사해 원하는 AI에 붙여 넣는다. AI는 받은 답을 재질문하지 않고 위 기록 규칙을 적용한다.

실제 설치 후에는 설치 경로, 수첩 URL, 질문지 버전, 선택한 기능, 연동 상태, 미완료 항목을 함께 인계한다. **질문지 버전은 수첩 버전이나 기능 업데이트 적용 버전과 다르다.** 질문을 변경할 때 이 문서와 웹 모델의 질문 ID·원문·선택지·분기 규칙을 함께 유지하고 검증한다.
