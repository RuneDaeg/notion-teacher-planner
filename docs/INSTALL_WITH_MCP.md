# Notion MCP/커넥터로 네 페이지 수첩 설치하기

이 경로는 AI에 연결된 Notion 쓰기 도구로 수첩을 구성한다. 별도 웹 앱이나 새로운 계정 서비스를 만들지 않는다. 도구가 읽기 전용이면 실제 생성 완료로 보고하지 않고 가능한 쓰기 경로를 안내한다.

## 준비와 설계 원본

1. `START_HERE.md`에서 이미 받은 학년도·학기·반·교과·선택 모듈과 상위 페이지를 확인한다. 같은 답을 다시 묻지 않는다.
2. 연결 계정과 사용자가 지정한 상위 일반 페이지를 확인한다. 기존 설치가 있으면 그 기록을 먼저 읽는다.
3. 실제 도구의 enhanced Markdown·뷰 DSL·블록 명세를 읽는다. REST 요청 형식과 MCP DSL을 섞지 않는다.
4. `DESIGN.md`, `docs/DEFAULT_TEMPLATE.md`, `teacher_planner/dashboard.json` 버전 3의 `workspace.pages`, `teacher_planner/blueprint.json`을 읽는다.

로컬 실행이 가능하면 `python -m teacher_planner plan --config .local/config.json --full`로 선택 모듈에 따른 전체 명세를 확인한다. `database_id`, `data_source_id`, `page_id`, `view_id`와 화면·섹션별 연결 DB ID를 각각 저장한다. MCP 기록은 `.local/mcp-install.json` 등에 보관하고 Python 상태와 섞지 않는다.

## 생성 순서

1. 상위 페이지 아래 학년도·학기를 표시한 루트 대시보드와 `학급 경영 & 학생 상담`, `교과 진도표 & 시간표`, `학사 캘린더 & PARA` 페이지를 만든다. 원본 DB용 `운영 자료`, `학생 기록`도 같은 수첩 안에 둔다.
2. 선택한 원본 DB를 만들고 반환된 data source ID로 관계를 연결한다. 기존 자료를 새로 복사하지 않는다. 전화번호·이메일·수식·갤러리 등은 실제 도구가 지원하는 정확한 유형으로 작성한다.
3. 담당 반·교과·영역을 넣고 원본 뷰를 만든다. `학년도`, `보관`, 날짜·상태 필터는 blueprint를 그대로 따른다. 데모를 요청하지 않았다면 실학생이나 가상 학생 기록을 넣지 않는다.
4. 네 페이지에 같은 실제 이동 링크를 만들고 `workspace.pages`의 섹션 순서로 네이티브 제목·콜아웃·링크·연결 DB를 배치한다.
5. 각 섹션의 첫 뷰로 연결 DB를 만든 뒤 같은 섹션의 후속 뷰를 그 DB의 보기 탭으로 추가한다. 선택하지 않은 모듈의 빈 섹션·링크는 만들지 않는다.
6. 교과 페이지의 주간 격자는 빈 교시·시각으로 시작한다. 학급 페이지의 조회·종례 메모도 빈 수동 영역으로 둔다. 학생 사진·연락처·요약 숫자를 참고 이미지에서 가져오지 않는다.
7. 생성된 실제 원본·부모·탭·필터를 검사한 뒤 [ACCEPTANCE.md](ACCEPTANCE.md)에 따라 화면을 확인한다.

모든 현재 학년도 뷰에는 설정 학년도와 `보관=false`, 보관함에는 해당 학년도와 `보관=true`를 적용한다. 학생 명렬표·학생 카드·관찰 학생, 출결 오늘·확인 필요·전체, 진도 반·교과·학기·보강 필요는 각각 같은 원본의 탭이다. 개인 정보가 있는 표를 숨기는 것만으로 권한이 분리되었다고 설명하지 않는다.

## 같은 섹션의 보기 탭 만들기

REST를 사용하는 경우 다음 순서로 만든다. MCP에서는 기존 연결 DB에 뷰를 추가하는 실제 도구 명세를 확인해 같은 구조를 만든다.

1. 첫 뷰에 원본 `data_source_id`와 대상 페이지의 `create_database.parent.page_id`를 지정한다.
2. 성공 응답의 `parent.database_id`를 **그 페이지·섹션의 연결 DB ID**로 저장한다.
3. 다음 뷰는 같은 원본 `data_source_id`와 저장한 연결 DB `database_id`로 생성한다. 이 요청에는 `create_database`를 넣지 않는다.
4. 같은 섹션의 모든 뷰가 같은 부모 DB와 원본을 사용하는지 확인한다. 다른 페이지의 동명 섹션은 별도의 연결 블록을 사용한다.

대시보드 캘린더는 `주간 캘린더 / 월간 캘린더` 탭을 갖는다. 둘 다 업무·일정 원본의 `일정` 속성을 사용하고 `configuration.view_range`만 week/month로 다르다. 학사 캘린더 페이지도 같은 원본으로 주간·월간 탭을 만들고, `마감` 속성을 사용하는 마감 탭을 같은 연결 DB에 추가한다.

주간·월간은 이름만 바꾸지 않는다. MCP DSL에서 실제 표시 범위를 지원하지 않으면 Notion UI 또는 지원하는 REST 뷰 설정을 사용하고 남은 작업을 명시한다. `WEEK` 같은 지원되지 않는 DSL을 추정해서 쓰지 않는다. 홈의 오늘 수업과 교과 페이지의 주간 시간표는 같은 교사 시간표 원본을 연결한다. 오늘 수업은 `오늘 수업=true` 날짜 필터를 사용한다. 수업을 업무·일정·To-Do·학사 캘린더에 복사하지 않는다. 기존 `업무·일정` 관계 속성은 유지하되 자동 연결·수리·해제하지 않으며, 이전 복사 일정도 자동 수정·삭제하지 않는다.

## Notion 네이티브 배치와 동작

Python REST 경로는 실제 연결 DB 뷰를 섹션별 전폭에 배치한다. 열에는 안내·콜아웃·페이지 링크를 넣는다. MCP가 열 안에 연결 DB를 배치하는 기능을 실제로 지원하면 사용할 수 있지만 제목·링크만 놓은 상태를 실제 데이터 표로 보고하지 않는다.

요청된 HEX 색상·서체·화면 픽셀·240px 사이드바는 `DESIGN.md`의 참고 기준이다. 네이티브 제목, 회색 설명, 상태별 색, 콜아웃과 기본 사이드바를 사용한다. 정확한 CSS나 고정 사이드바를 설치했다고 안내하지 않는다. 전체 너비·표 열 폭은 실제 UI에서 필요에 맞춰 확인한다.

빠른 실행은 생성한 DB를 여는 링크다. 새 기록은 Notion의 새로 만들기를 이용한다. 사용자가 상태·확인·태그를 편집하면 그 원본 기록에 반영되는 기본 동작을 사용한다. 자동 업로드·성공 토스트·외부 알림을 가장하지 않는다. 숫자 집계가 필요하면 실제 지원되는 UI에서 개수·평균 계산을 설정하고 결과를 확인한다.

학교 공유 페이지·설문·NEIS·에듀파인 주소는 `dashboard.links`에서 입력한 선택형 바로가기다. 비어 있으면 설정 안내를 표시하고 실제 학교 주소를 추정하지 않는다. 링크를 로그인이나 데이터 동기화 연결로 설명하지 않는다.

PARA 콜아웃 네 열은 프로젝트·담당 영역·자료·보관함으로 연결한다. 프로젝트 상태 보드는 프로젝트 DB의 상태를 관리한다. 모든 PARA 항목을 드래그 한 번으로 서로 다른 DB 사이에 이동시키는 기능은 제공하지 않는다.

## 수식과 메모

오늘 수업·상담·출결은 원본 날짜와 오늘 날짜를 비교하는 수식·필터를 사용한다. 마감과 평가 D-Day는 원본 날짜로 계산하며 빈 날짜나 완료·취소 기록을 예정 업무로 표시하지 않는다. 학생 관찰 태그와 집중 관찰 체크는 실제 학생 원본에 저장한다. 조회·종례 콜아웃 메모는 수동 영역이며 자동 날짜 기록·복사·초기화가 없다.

MCP로 만든 시간표 격자는 Python 설치 상태와 자동 연결되지 않는다. MCP 담당자가 날짜가 검증된 원본 기록으로 해당 주의 표를 갱신하고 표시 주간을 함께 확인한다. 공식 NEIS 출결·학적 쓰기, 컴시간 푸시, 클라우드 상시 실행, 자동 메시지 발송은 구현되어 있지 않다. 공개 학사일정 API 조회와 Notion 일정 반영은 별도 [SCHOOL_CALENDAR.md](SCHOOL_CALENDAR.md)를 따른다. Python 동기화에는 Python 설치 상태가 필요하므로 MCP 설치 ID를 임의로 섞지 않는다.

## 급식 영역과 양식 모음

홈에 식단 표시용 콜아웃과 양식 모음으로 가는 링크를 둔다. [MEALS.md](MEALS.md)의 실제 학교·날짜 검증을 마친 공개 식단만 반영하며 최초 설치에는 연결 안내를 둔다. 메뉴의 알레르기 번호를 보존하고 자료 없음·조회 오류를 구분한다. 급식은 DB 행이나 일정으로 만들지 않는다.

[FORMS.md](FORMS.md)의 선택·모듈·담임 조건에 맞게 빈 양식 페이지를 만든다. 교사가 승인한 상담·학부모 연락·회의록·수업·평가·조회/종례 구조만 사용하고 실제 인물·기록을 예시로 넣지 않는다. 이는 복사용 페이지 양식이다. 실제 도구로 DB 네이티브 템플릿을 따로 등록하지 않았다면 새로 만들기 메뉴에 등록됐다고 보고하지 않는다.

기존 MCP 설치는 이미 있는 페이지·블록 ID를 확인하고 누락된 추가 영역만 만든다. Python `setup-extras`와 `meals-sync`는 완료된 Python 설치 상태를 사용하므로 MCP ID를 임의로 그 상태에 넣지 않는다. 생성 ID와 전용 급식 블록 소유 기록은 기존 MCP 설치 기록에 보관한다. 교사가 수정한 양식이나 다른 본문을 재설치로 덮어쓰지 않는다.

## 중단·재실행

권한 부족·뷰 미지원·응답 유실 시 이미 만든 URL·ID를 보존하고 [RECOVERY.md](RECOVERY.md)를 따른다. 같은 섹션의 첫 뷰가 생성되었다면 후속 탭은 그 부모 DB를 재사용한다. 기존 DB를 삭제하거나 새 연결 블록을 반복해서 만드는 방식으로 실패를 숨기지 않는다.

새 버전은 새 설치 기본값이다. 이전 설치 상태를 삭제하거나 사용자 블록을 재배치하지 않는다. 기존 수첩 수정은 대상과 유지할 기록을 확인한 별도 작업으로 진행한다. 실제 생성·검증한 내용과 미리보기·모의 테스트를 구분해 최종 보고한다.
