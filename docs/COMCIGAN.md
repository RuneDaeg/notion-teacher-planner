# 컴시간과 시간표 가져오기

## 두 가지 경로

| 경로 | 필요한 입력 | 수행하는 일 |
| --- | --- | --- |
| 파일 가져오기 | 날짜가 있는 정규 CSV/JSON | 형식 검증 → Notion 교사 시간표 반영 |
| 컴시간 웹 조회·동기화 | 학교 코드 + 교사 번호 | 선택한 교사의 요청 주 조회 → 날짜 검증 → 선택적으로 Notion 반영 |

웹 연동은 **공식 공개 API 계약을 확인하지 못한 비공식 구현**이며 기본 설치 시 켜지지 않는다. 교사 웹에서 읽을 수 있는 정보만 사용하고, 로그인·인증·접근 제한을 우회하지 않는다. PC에 컴시간알리미를 설치할 필요는 없다. 웹 구조나 서비스 제공 범위가 바뀌면 수정이 필요할 수 있다. 현재 교사 웹은 HTTP를 사용하므로 학교 코드와 교사 번호를 암호화된 로그인 자격증명으로 취급하지 않는다. 이 조회 경로에 Notion 토큰을 전송하지 않는다.

웹 어댑터가 해석하는 범위는 **월~금, 1~3학년, 1~8교시**다. 이 범위를 벗어나거나 합반으로 동일 교시에 원수업이 중복되면 임의로 합치지 않고 오류로 중단한다. 다른 학교 운영 방식은 날짜별 파일 가져오기를 사용한다.

제공하지 않는 기능: 변경 즉시 받는 푸시, 서버 예약 작업 자동 설치, 로그인 자동화, Notion에서 컴시간으로 역전송. `--watch`는 실행 중인 프로세스가 정해진 간격으로 다시 조회하는 기능이다.

파일 가져오기와 컴시간 동기화는 **교사 시간표 DB만** 추가·갱신한다. 교과 페이지의 주간 시간표와 홈의 `오늘의 수업`이 같은 원본을 사용한다. 홈에서는 오늘 날짜에 해당하는 수업을 보여 준다. 업무·일정·To-Do·학사 캘린더에 수업을 복사하지 않는다.

## 학교 코드·교사 번호로 한 주 조회

학교 코드와 교사 번호는 해당 학교에서 확인한 값을 사용한다. 교육행정기관의 학교 코드나 학생 시간표의 번호와 같다고 가정하지 않는다. 번호는 학교의 자료 갱신에 따라 달라질 수 있으므로 새 학기에는 조회 결과의 교사와 담당 수업을 확인한다.

```bash
python -m teacher_planner comcigan-week --school-code 학교코드 --teacher-id 교사번호 --output .local/comcigan-week.json

# 특정 날짜가 속한 주 조회
python -m teacher_planner comcigan-week --school-code 학교코드 --teacher-id 교사번호 --date 2026-09-28 --output .local/comcigan-week.json
```

학교 코드와 교사 번호는 각각 `COMCIGAN_SCHOOL_CODE`, `COMCIGAN_TEACHER_ID` 환경 변수로 대신 제공할 수 있다. `--date`를 생략하면 서울 기준 이번 주를 조회한다. 출력 경로의 기본값은 `.local/comcigan-week.json`이다. 이 명령은 Notion 토큰 없이 실행할 수 있고 Notion을 읽거나 수정하지 않는다.

출력 JSON에는 선택한 학교·교사와 해당 교사의 주간 수업만 담는다. 학교 전체 교사 명단이나 원본 응답은 저장하지 않는다. 조회된 원본의 실제 주간 날짜를 확인하며 **현재 시간표를 요청한 다른 주의 시간표인 것처럼 날짜만 바꾸지 않는다.** 해당 주가 제공되지 않거나 날짜를 검증할 수 없으면 오류로 중단한다. 원본의 열람 제한 때문에 요청 주의 금요일까지 확인할 수 없는 경우에도 부분 결과로 동기화하지 않는다. 접속·파싱 실패 역시 빈 시간표와 구분한다.

실제 조회 결과는 `.local/` 또는 `private/`에 둔다. 공개 저장소에는 실제 학교 코드·교사 번호·교사 이름·시간표를 올리지 않는다.

## 기존 Notion 수첩에 반영

Notion 수첩을 먼저 설치하고 기존 `.local/config.json`, `.local/state.json`을 사용한다. 웹 조회에 필요한 값은 학교 코드와 교사 번호지만, Notion 반영에는 연결 토큰·설치 상태와 해당 수업의 반·교과 설정도 필요하다.

```bash
# 컴시간 조회와 입력 검증만 수행; Notion에 쓰지 않음
python -m teacher_planner comcigan-sync --school-code 학교코드 --teacher-id 교사번호 --config .local/config.json

# NOTION_TOKEN이 환경 변수에 설정된 상태에서 실행
python -m teacher_planner comcigan-sync --school-code 학교코드 --teacher-id 교사번호 --config .local/config.json --state .local/state.json --apply
```

`--date YYYY-MM-DD`로 다른 주를 지정할 수 있다. 웹의 학년·반은 기본적으로 `1학년 1반` 형식의 이름으로 변환한다. 조회된 모든 반과 교과가 기존 설정에 있어야 하며, 이름이 다르면 아래 매핑 파일을 지정한다. Notion 설정의 시간대는 `Asia/Seoul`이어야 한다. 첫 반영 시 학교 코드·교사 번호·교사 이름을 설치 상태에 연결하며, 이후 다른 값이 오면 기존 수업의 덮어쓰기를 막기 위해 중단한다.

### 학교·교사 연결 변경 절차

1. 실행 중인 `--watch`를 중지하고, 학교 코드·교사 번호·교사 이름과 실제 담당 수업을 확인한다. 교사 번호가 재배정되었는지 확인한다.
2. 다른 학교·교사의 수첩이 필요하면 새 수첩과 별도 설치 상태 경로를 사용한다. 기존 수첩의 기록은 남는다.
3. 같은 교사의 번호만 바뀐 경우에는 기존 설치 상태를 백업하고 원본과 기존 시간표를 검토한다. 연결 정보의 정정과 기존 행 정리는 자동화하지 않는다. AI가 오류를 없애려고 `comcigan_source`를 임의로 초기화하지 않는다.

연결 제한을 해제해도 기존 행이 자동 삭제·통합되는 것은 아니다. 원본 식별값 변경 후 기존 기록과 새 기록이 중복되는지 확인해야 한다.

### 학교에 맞는 교시 시각과 이름 설정

컴시간 응답으로 실제 종료 시각을 확인할 수 없을 때 수업 길이를 45분·50분으로 추정하지 않는다. 교시 시각을 설정하지 않으면 Notion 수업일에는 날짜만 기록한다. 시간표에 정확한 시각이 필요하면 `.local/period-times.json`에 수업이 있는 각 교시의 실제 시각을 적는다.

```json
{
  "1": {"start": "09:00", "end": "09:50"},
  "2": {"start": "10:00", "end": "10:50"}
}
```

이름이 다르면 `.local/comcigan-mapping.json`에 **원본 학급 코드·교과 이름 → 기존 수첩 이름**을 적는다. `classes`의 키는 `학년-반` 코드이고, `subjects`의 키는 원본 교과 이름이다. 파일은 선택 사항이며 이름이 일치하는 수업은 매핑하지 않아도 된다.

```json
{
  "classes": {"1-1": "1학년 1반"},
  "subjects": {"영어A": "영어"}
}
```

```bash
python -m teacher_planner comcigan-sync --school-code 학교코드 --teacher-id 교사번호 --config .local/config.json --period-times .local/period-times.json --mapping .local/comcigan-mapping.json
```

검증 후 같은 명령에 `--apply`를 추가하면 반영한다. 시각·이름 설정은 로컬 보조 파일이며 학생 명단과는 관계없다.

### 10분마다 갱신

```bash
python -m teacher_planner comcigan-sync --school-code 학교코드 --teacher-id 교사번호 --config .local/config.json --apply --watch --interval 600
```

필요한 `--period-times`, `--mapping`, `--state` 옵션을 함께 지정한다. `--watch`는 `--apply`와 함께만 사용할 수 있고, 과거 주에 고정되지 않도록 `--date`와 함께 사용할 수 없다. 매번 서울 기준 이번 주를 조회한다. `--interval`은 초 단위이며 최소 300초다. `Ctrl+C`로 종료하며, PC 종료·절전·프로세스 종료 중에는 갱신하지 않는다. 예약 작업이나 외부 서버는 자동으로 만들지 않는다. 실행 중 오류가 나면 중단하므로 원인을 확인한 뒤 다시 실행한다.

변경이 없는 수업에는 Notion 수정 요청을 보내지 않는다. 시간표의 `동기화 시각`은 실제로 내용을 반영한 시각이며, 마지막으로 조회에 성공한 시각은 로컬 설치 상태의 `comcigan_last_checked_at`에 기록한다.

## 파일의 정규 형식

컴시간 공식 질의응답에는 엑셀 출력 안내가 있으나 제품·권한에 따라 제공 형식이 다를 수 있다. **이 도구가 임의의 컴시간 원본 엑셀을 바로 읽는 것은 아니다.** 학교에서 확보한 파일을 아래 형식으로 정리한다.

UTF-8 또는 UTF-8 BOM CSV. 열 순서는 자유지만 아래 8개 열이 모두 필요하다. JSON은 같은 키를 가진 객체 배열이다. 예시는 `examples/timetable.csv`, `examples/timetable.json`이다. `comcigan-week`의 조회 결과 JSON은 이 파일 가져오기 형식과 구분하며, 웹 결과 반영에는 `comcigan-sync`를 사용한다.

| 열 | 예시 | 규칙 |
| --- | --- | --- |
| date | 2026-09-28 | 실제 날짜, 설정 학년도 3월~다음 해 2월 |
| period | 1 | 1~20 정수 |
| start | 09:00 | 학교의 실제 교시 시작 시각 |
| end | 09:50 | 같은 날, 시작 이후 |
| class_name | 1학년 1반 | 설정·Notion 학급 이름과 정확히 일치 |
| subject | 영어 | 설정 교과와 일치 |
| room | 101 | 비워도 됨 |
| status | 예정 | 예정 / 변경 / 휴강 / 완료 |

```bash
python -m teacher_planner import-timetable private/timetable.csv --config .local/config.json
python -m teacher_planner import-timetable private/timetable.csv --config .local/config.json --apply
```

첫 명령은 오프라인 형식 검사만 한다. 두 번째는 원격 학급과 기존 외부 ID를 모두 조회한 후 추가·갱신한다. 기존 행의 변경 전후 차이표를 보여주는 기능은 없다. 학급이 없거나 중복 ID가 있으면 쓰기 전에 중단한다.

## 변경·휴강·재실행 규칙

파일 고유키는 **학년도 + 설정한 교사 + 실제 날짜 + 교시**, 웹 고유키는 **컴시간 학교 코드 + 교사 번호 + 실제 날짜 + 교시**의 해시다. 각 경로에서 교과·반·교실·시각이 바뀌어도 같은 날짜·교시는 기존 교사 시간표 행을 갱신한다. 파일로 넣은 수업과 웹에서 가져온 수업을 자동으로 합치지는 않는다. 이미 파일로 넣은 주에 웹 동기화를 시작하면 중복될 수 있으므로, 처음 전환할 때 중복 날짜를 확인하고 필요한 기존 행 정리를 별도로 진행한다.

한 교사의 같은 날짜·교시가 둘이면 거부한다. 파일 방식의 합반은 하나의 학급 이름으로 설정한다. 겹치는 수업 시각도 거부한다.

**누락 행은 삭제하지 않는다.** 원본에서 빠졌다는 이유만으로 휴강인지 데이터 유실인지 판단하지 않는다. 파일에서는 `휴강` 행으로 명시한다. 웹에서는 원수업이 있고 현재 셀이 명시적인 빈칸(`0`)인 경우만 휴강으로 반영한다. 교시 자체가 응답에서 누락된 경우는 휴강으로 보지 않는다. 휴강 상태는 시간표에 남으며 오늘 수업·변경·휴강 보기에서도 원본 상태를 확인한다. 업무·일정은 수정하지 않는다. 주가 바뀌면 날짜가 달라 새 행이 된다. 학기 전체 수업을 요일만으로 복제하거나 공휴일·재량휴업일을 추정하지 않는다.

부분 실패 후 같은 데이터로 재실행하면 원격 외부 ID로 기존 행을 다시 찾는다. 생성 결과가 불확실하면 [RECOVERY.md](RECOVERY.md)대로 복구한다. 조회 실패나 지원하지 않는 응답에서는 Notion 반영을 시작하지 않는다.

## 이전 버전에서 만든 일정

이전 버전이 업무·일정 DB에 복사한 수업 일정과 시간표의 `업무·일정` 관계는 그대로 둔다. 새 가져오기·동기화는 관계를 자동 연결·수리·해제하지 않고 과거 일정도 갱신·취소·삭제하지 않는다. 이 변경만으로 기존 캘린더에서 과거 수업이 사라졌다고 보고하지 않는다. 복사본을 정리하려면 외부 ID와 대상 기간으로 실제 기록을 식별한 별도 작업이 필요하다.

## 검증 범위

공개 교사 웹 클라이언트의 응답 처리 방식을 확인해 독립적으로 작성했으며, 제3자 구현 코드를 복사하지 않았다. 공개 클라이언트 접근·모의 응답 테스트와 실제 학교 조회는 다르다. 저장소 제작 시 실제 학교 코드·교사 번호를 제공받지 않았으므로 **특정 학교에서의 주간 시간표 조회·Notion 반영 검증은 수행하지 않았다.** 처음 연결할 때 [ACCEPTANCE.md](ACCEPTANCE.md)의 컴시간 확인 항목을 수행한다.
