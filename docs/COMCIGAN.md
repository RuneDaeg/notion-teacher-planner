# 컴시간과 시간표 가져오기

## 현재 제공 범위

제공: **날짜가 있는 CSV/JSON → 검증 → Notion 교사 시간표 + 연결된 캘린더 일정**.

미제공: 컴시간 실시간 API 호출, 교사용 로그인 자동화, 비공식 스크래핑, 서버 스케줄러, Notion 변경사항의 컴시간 역전송. 조사한 공식 문서에서는 공개 자동 연동 API 계약을 확인하지 못했다. API가 절대 없다고 단정하는 것은 아니다.

컴시간 공식 질의응답에 엑셀 출력 안내가 있지만 제품과 권한에 따라 화면과 제공 형식이 다를 수 있다. 학교에서 실제 받을 수 있는 파일을 확인하고 아래 정규 형식으로 변환한다. **이 도구가 임의의 컴시간 원본 엑셀을 바로 읽는 것은 아니다.**

## 정규 형식

UTF-8 또는 UTF-8 BOM CSV. 열 순서는 자유지만 아래 8개 열이 모두 필요하다. JSON은 같은 키를 가진 객체 배열이다. 예시는 `examples/timetable.csv`, `examples/timetable.json`이다.

| 열 | 예시 | 규칙 |
| --- | --- | --- |
| date | 2026-09-28 | 실제 날짜, 설정 학년도 3월~다음 해 2월 |
| period | 1 | 1~20 정수 |
| start | 09:00 | 학교의 실제 교시 시작 시각 |
| end | 09:50 | 같은 날, 시작 이후 |
| class_name | 1학년 1반 | 설정·Notion 학급 이름과 정확히 일치 |
| subject | 영어 | 설정 교과와 일치 |
| room | 101 | 비워도 됨 |
| status | 예정 | 예정 / 변경 / 휴강 / 완료 |

```bash
mkdir -p private
# 변환한 파일을 private/timetable.csv로 저장
python -m teacher_planner import-timetable private/timetable.csv --config .local/config.json
python -m teacher_planner import-timetable private/timetable.csv --config .local/config.json --apply
```

첫 명령은 오프라인 형식 검사만 한다. 두 번째는 원격 학급과 기존 외부 ID를 모두 조회한 후 추가·갱신한다. 기존 행의 변경 전후 차이표를 보여주는 기능은 아직 없다. 학급이 없거나 중복 ID가 있으면 쓰기 전에 중단한다.

고유키는 **학년도 + 교사 + 실제 날짜 + 교시**의 해시다. 교과·반·교실·시각이 바뀌어도 같은 날짜·교시는 기존 행을 갱신한다. 한 교사의 같은 날짜·교시가 둘이면 거부한다. 합반은 하나의 학급 이름으로 설정한다. 한 파일 안에서 겹치는 수업 시간도 거부한다.

**누락 행은 삭제하지 않는다.** 빠진 수업은 데이터 유실인지 휴강인지 알 수 없기 때문이다. 취소할 수업은 `휴강` 행으로 명시한다. 시간표에는 휴강 상태가 남고 연결 일정은 취소되어 활성 캘린더에서 빠진다. 주가 바뀌면 날짜가 달라 새 행이 된다. 학기 전체 수업을 요일만으로 무작정 복제하지 않으며 공휴일·재량휴업일을 추정하지 않는다.

부분 실패 후 같은 파일로 재실행하면 원격 외부 ID로 기존 행을 다시 찾는다. 생성 결과가 불확실하면 `docs/RECOVERY.md`대로 복구한다. 예약 실행은 포함하지 않는다.

## 향후 컴시간 어댑터 계약

학교 또는 제공자가 허용한 연동 수단이 확인되면 별도 어댑터가 다음 정보로 위 정규 JSON을 출력하게 한다.

1. 학교 식별자와 교사 식별자, 요청한 실제 날짜 범위
2. 해당 주 원본 버전/조회 시각과 교시별 시작·종료 시각
3. 날짜별 반·교과·교실·변경·휴강 상태
4. 인증 만료·파싱 실패·해당 주 미제공을 ‘빈 시간표’와 구분하는 오류

어댑터는 JSON만 생성하고 Notion 토큰을 받지 않는다. 검증된 JSON을 기존 가져오기 명령에 전달한다. 별도 프로세스를 임의 문자열 명령으로 실행하는 기능은 제공하지 않는다. 비공식 어댑터를 선택한다면 교사의 동의와 해당 서비스 이용 조건을 확인하고 공개 저장소에는 자격증명을 넣지 않는다.
